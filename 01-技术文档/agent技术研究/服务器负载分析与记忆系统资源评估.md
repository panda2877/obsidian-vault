## 五、可支持的记忆系统模式分析

### 模式 A：Neo4j 图数据库（GBrain）

| 需求 | 实际 |
|------|------|
| 内存需求 | 1~2 GB（Neo4j 最低要求） |
| 当前可用 | ~500MB 物理 + Swap 已满 |
| **结论** | ❌ **完全不可行**，必定 OOM |

### 模式 B：Qdrant 向量数据库 + 本地 Embedding 模型（Hindsight 完整版）

| 需求 | 实际 |
|------|------|
| Qdrant 进程 | 200~500 MB |
| 本地 Embedding 模型（bge-small） | ~300 MB |
| 总计 | 500~800 MB |
| 当前可用 | ~500MB（需挤占其他服务） |
| **结论** | ❌ **不可行**，风险极高 |

### 模式 C：Chroma（嵌入式）+ API Embedding（轻量 Hindsight）

| 需求 | 实际 |
|------|------|
| Chroma in-process | 50~100 MB（随 Hermes 进程共享） |
| API Embedding（OpenAI/MiniMax） | 0 MB（远程调用） |
| 总计 | 50~100 MB |
| 当前可用 | ~500MB |
| **结论** | ⚠️ **勉强可行**，但很紧张，无容错空间 |

### 模式 D：SQLite + sqlite-vss / LanceDB 嵌入式（最轻量方案）

| 需求 | 实际 |
|------|------|
| sqlite-vss/LanceDB in-process | 20~50 MB |
| API Embedding | 0 MB（远程调用） |
| 总计 | 20~50 MB |
| 当前可用 | ~500MB |
| **结论** | ✅ **可行**，这是当前唯一稳妥选项 |

### 模式 E：纯内存 FAISS / 无外部依赖方案

| 需求 | 实际 |
|------|------|
| FAISS 索引（10万条 1536维） | ~600 MB |
| 当前可用 | ~500MB |
| **结论** | ❌ **不可行**，FAISS 索引太大 |

## 六、结论与建议

### 🔴 核心判断

**在当前 3.6GB 内存配置下，只能支持"嵌入式向量存储 + API 远程 Embedding"的最轻量方案。** 任何需要独立数据库进程的方案（Neo4j/Qdrant/Milvus/FAISS Server）都不可行。

### ✅ 推荐落地方案：SQLite-vss + API Embedding

```
架构：
  ┌─────────────────────────────────┐
  │  Hermes Agent（现有，404MB）      │
  │  ├── MEMORY.md（现有，保留）      │
  │  ├── 向量检索层（新增，+30MB）    │
  │  │   └── sqlite-vss 嵌入式       │
  │  └── API Embedding（0MB）        │
  │      └── text-embedding-3-small  │
  │          或 MiniMax embedding    │
  └─────────────────────────────────┘

资源增量：+30~50MB 内存，+0MB 本地服务
Embedding 成本：~$0.02/百万token（极便宜）
```

**收益**：
1. 每次对话不再全量读入 MEMORY.md，用语义检索找相关记忆 → 预估节省 60~80% Prompt Token
2. 记忆条目可扩展到 1万+，而不受字符数限制
3. 为未来升级到独立向量数据库打基础

**风险**：
1. SQLite-vss 的 ANN 精度不如 Qdrant（但对我们几千条规模足够）
2. 依赖外部 Embedding API，断网时无法写入（但可降级为全量读入）

### 🔧 如果预算允许，推荐升级内存

| 升级到 | 可支持方案 | 月成本增加 |
|--------|----------|----------|
| 8 GB | Chroma + API Embedding，有充足容错 | ~¥50~100/月 |
| 16 GB | Qdrant + 本地 Embedding（bge-small），完整 Hindsight | ~¥200/月 |
| 32 GB | Neo4j + Qdrant 混合（GBrain + Hindsight） | ~¥400/月 |

## 七、其他可优化项（免费释放内存）

在升级之前，有几项可以**零成本释放内存**：

| 项目 | 内存可释放 | 难度 |
|------|----------|------|
| 调小 systemd-journald 缓冲 | ~100~150 MB | 中（需改配置） |
| 关闭 Docker daemon（未跑容器） | ~18 MB | 低 |
| 定期重启 Hermes Agent（防内存泄漏） | 不定 | 可配 cronjob |

> **注**：Dashboard Vite 开发服务器虽然吃 ~316MB，但因其有持续开发需求，生产化并不能真正省下这块内存（开发时仍会重新启动）。不计入可优化项。**
