## 一、v1.4 L3-c/L3-d 的实际问题

### L3-c — "固化启动时读取日志流程"

**v1.4 落地内容**：在 MEMORY.md 里加了「启动流程」章节，文字写的是"读取日志"。

**实际问题**：memories/ 目录里没有日志文件，读了个寂寞。

```
当前 memories/ 目录内容：
├── MEMORY.md ✅（只有这个）
├── MEMORY.md.lock
└── （没有 YYYY-MM-DD.md 日志文件）
```

### L3-d — "固化任务交接写入日志流程"

**v1.4 落地内容**：在 MEMORY.md 里加了「任务交接规范」章节，文字写的是"必须写入日志"。

**实际问题**：没有人在交接时真的写日志，也没有触发机制。

---

## 二、修正思路

**两步并作一步：**

1. **修正**：把 L3-c/L3-d 从"规范文字"变成"实际触发"
   - 触发机制：每完成一个有意义的任务阶段 → 写快照
   - 交接时：交出方写快照，接替方读快照
   - 启动时：读快照，恢复未完成任务现场

2. **叠加**：快照机制作为实际日志载体，不依赖原有"YYYY-MM-DD.md 日志"设计

**关键决策**：不再依赖 cronjob 写每日日志（因为没有日志内容来源），改用快照作为任务进度载体。

## 三、快照格式

```markdown
## 任务快照 {YYYY-MM-DD HH:MM}

- **任务**：{一句话描述}
- **进度**：{X/Y 或 百分比}
- **卡点**：{如有，描述遇到的障碍}
- **下一步**：{最关键的1-2个动作}
- **继续提示**：{给接续者的关键上下文：命令/路径/关键决策}

---
*快照版本：v1 | 来源：如音*
```

## 六、快照 vs 巡检日志

| | 快照 | 巡检日志 |
|---|---|---|
| **来源** | 任务进行中实时写入 | cronjob 定时生成 |
| **内容** | 任务进度/卡点/下一步 | 记忆库健康检查 |
| **读者** | 接续的姐妹/自己 | 银月巡检 |
| **格式** | 固定模板 | 巡检报告格式 |
| **是否必须** | ✅ 核心 | cronjob 已落地 |

---

## 七、快照生命周期

```
写入快照（任务中）
    │
    ▼
任务完成 → 删除快照 ✅
    │
    ▼
7 天无操作 → 自动清理（可选 cronjob）
```

**快照清理 cronjob（可选）：**
```bash
hermes cron create \
  --name "快照清理" \
  --profile xingruyin \
  --message "清理 memories/snapshots/ 下 7 天前且已完成任务的快照：
find ~/.hermes/profiles/xingruyin/memories/snapshots/ -name 'snapshot_*.md' -mtime +7 -delete
echo '快照清理完成'" \
  --schedule "0 7 * * *" \
  --deliver origin
```
