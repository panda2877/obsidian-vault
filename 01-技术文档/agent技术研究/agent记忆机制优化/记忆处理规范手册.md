> 用途：指导记忆变更工作的标准操作手册

## 一、架构总览

### 1.1 三层记忆体系

| 层级 | 存储位置 | 容量/特征 | 加载方式 |
|------|---------|---------|---------|
| 第一层：会话级 | LLM context window | Token 上限，自动管理 | 自动，会话结束即销毁 |
| 第二层：中期记忆 | `memories/YYYY-MM-DD.md` | 无限制 | 需主动读取 |
| 第三层：长期记忆 | `MEMORY.md` + `USER.md` | 2200 + 1375 字符限额 | 每次启动自动加载 |

### 1.2 路径速查表

| 姐妹 | MEMORY.md | USER.md | memories/ 目录 | SOUL.md |
|------|-----------|---------|---------------|---------|
| 银月（main） | `~/.hermes/memory/MEMORY.md` | `~/.hermes/memory/USER.md` | `~/.hermes/memories/` | `~/.hermes/memory/SOUL.md` |
| 如音 | `~/.hermes/profiles/xingruyin/memories/MEMORY.md` | `~/.hermes/profiles/xingruyin/memories/USER.md` | `~/.hermes/profiles/xingruyin/memories/` | `~/.hermes/profiles/xingruyin/SOUL.md` |
| 思月 | `~/.hermes/profiles/wensiyue/memories/MEMORY.md` | `~/.hermes/profiles/wensiyue/memories/USER.md` | `~/.hermes/profiles/wensiyue/memories/` | `~/.hermes/profiles/wensiyue/SOUL.md` |
| 紫灵 | `~/.hermes/profiles/ziling/memories/MEMORY.md` | `~/.hermes/profiles/ziling/memories/USER.md` | `~/.hermes/profiles/ziling/memories/` | `~/.hermes/profiles/ziling/SOUL.md` |
| 公共配置 | `~/.hermes/profiles/shared/role-responsibility.md` | — | — | — |

> **关键差异**：银月（main-agent）路径无 `profiles/` 中间层；其他姐妹路径有 `memories/` 两级嵌套。

### 1.3 各姐妹记忆分工

| 姐妹 | MEMORY.md 重点 | USER.md 重点 |
|------|---------------|-------------|
| 银月 | 项目全局状态、当前任务进度、协作路由规则 | 老大沟通偏好 |
| 如音 | 技术规范、服务器环境、已知Bug、工具配置 | 分工边界、技术偏好 |
| 思月 | 文档归档状态、知识库结构、归档流程规范 | 老大文档偏好 |
| 紫灵 | 需求创意规范、产品设计知识、创意标准 | 老大创意偏好 |

### 1.4 公共配置管理原则

- **各 Agent 私有记忆**：写在自己目录，只读自己的 → 无冲突
- **公共配置**（角色职责表等）：大家只读，银月唯一写入 → 无冲突
- **启动时额外读取**：`~/.hermes/profiles/shared/role-responsibility.md`

## 二、中期记忆（日志）处理规范

### 2.1 日志文件格式

路径：`~/.hermes/profiles/{name}/memories/YYYY-MM-DD.md`（如音/思月/紫灵）
路径：`~/.hermes/memories/YYYY-MM-DD.md`（银月）

```markdown
# {YYYY-MM-DD} 工作日志 — {姐妹名}

## 今日完成
-

## 进行中
-

## 待处理
-

## 关键决策
-

## 遗留问题
-
```

### 2.2 任务交接日志格式

当姐妹之间需要交接任务时，交出方必须写入日志：

```markdown
## 任务交接：{任务名} → {接替姐妹}
- 当前进度：...
- 关键信息：...
- 注意事项：...
- 接替者需要：...
```

### 2.3 日志记忆时间窗口

- **窗口范围**：前一天北京时间 03:00 → 当天北京时间 03:00（24小时滑动窗口）
- **时区**：Asia/Shanghai (CST, UTC+8)

## 三、长期记忆（MEMORY.md）处理规范

### 3.1 字符限额

| 文件 | 限额 | 压缩触发线 |
|------|------|----------|
| MEMORY.md | 2200 字符 | > 1800 字符 |
| USER.md | 1375 字符 | — |

### 3.2 MEMORY.md 精简模板

```markdown
# {姐妹名} - 记忆档案

## 老大信息
- 身份/位置/沟通偏好（精简，不超过 3 行）

## 分工边界
- 我的职责：...
- 其他姐妹职责：...

## 技术环境
- 关键路径/工具/规范（精简，不超过 5 行）

## 重要规范
- 本项目中经确认必须遵守的规则（精简，不超过 5 条）

---

*由心跳机制维护，自动更新*
```

### 3.3 压缩触发条件与处理

**触发条件**：MEMORY.md 实际字符数 > 1800

**处理流程**：
1. 清理失效的临时记录
2. 精简长表述
3. 保留核心规范

**"无法精简"时的处理**：
- 在当天日志中记录"本次无需压缩"
- 若连续 3 次均无需压缩 → 提示老大将部分规范迁移至独立文件或提炼为 skill

### 3.4 启动时读取日志流程（固化在 MEMORY.md）

各姐妹在 MEMORY.md 开头固化以下流程：

```markdown
## 启动流程
每次启动时：
1. 读取 memories/ 目录下近 3 天的日志文件
2. 从日志中提取「进行中」和「待处理」事项
3. 若有未完成的上文任务，主动询问老大是否接续
4. 额外读取 ~/.hermes/profiles/shared/role-responsibility.md，作为记忆的一部分
```

> **注意**：银月的路径为 `~/.hermes/memories/`，如音/思月/紫灵为 `~/.hermes/profiles/{name}/memories/`。

## 四、心跳巡检机制

### 4.1 巡检 Cronjob 架构

| 类型 | 触发时间 | 数量 | 维护方 |
|------|---------|------|-------|
| 各Agent独立巡检 | 每天 21:00（北京时间） | 3条（如音/思月/紫灵各一） | 各姐妹自行维护 |
| 全局汇总巡检 | 每天 03:00（北京时间） | 1条（银月） | 银月维护 |

### 4.2 独立巡检内容（各姐妹21:00）

```
1. 读取 memories/ 近 3 天日志
2. 提取新出现的规范/决策/偏好
3. 更新 MEMORY.md（新增重要内容）
4. 清理失效的临时记录
5. 若 MEMORY.md > 1800 字符，执行精简压缩
6. 评估是否有长规范可提炼为独立 skill
7. 在当天 memories 日志中记录本次巡检结果
```

### 4.3 全局巡检内容（银月03:00）

```
1. rglob扫描 ~/.hermes/skills/ 下所有 SKILL.md，检查 metadata 完整性
2. 读取 bypass.log，统计拦截次数
3. 计算各 sub-agent 积分（基于本周操作日志）
4. 生成巡检报告，推送飞书
5. 发现未归档内容 → 通知思月
```

### 4.4 巡检检查清单

```
□ 读取 memories/ 近 3 天日志
□ 提取新出现的规范/决策/偏好
□ 更新 MEMORY.md（新增重要内容）
□ 清理失效的临时记录
□ 若 MEMORY.md > 1800 字符，执行精简压缩
□ 评估是否有长规范可提炼为独立 skill
□ 在当天 memories 日志中记录本次巡检结果
□ Skill 文件检查：新建 skill、trigger_scenes 待补全
□ 休眠检测：last_used > 90天 → 标记 dormant
□ sub-agent 积分状态检查
□ 违规拦截统计
```

## 五、Skill 管理规范

### 5.1 索引机制：Native Only + Metadata in SKILL.md

- **标准字段**（进 manifest）：`name`、`description`、`category`、`tags`
- **metadata 字段**（按需读取，不进 manifest）：`owner`、`trigger_scenes`、`inferred_triggers`、`dependencies`、`match_stats`

### 5.2 SKILL.md metadata 结构

```yaml
---
name: systematic-debugging
description: Bug排查、故障诊断、报错分析
category: software-development
tags: [bug, error, debugging, crash]
metadata:
  owner: xingruyin
  trigger_scenes:
    - Bug排查
    - 故障诊断
    - 报错分析
  inferred_triggers: []
  dependencies: []
  match_stats:
    total: 15
    true_positive: 13
    false_positive: 2
    last_used: "2026-04-28"
---
```

### 5.3 owner 归属规则

| owner | 归属 | 说明 |
|-------|------|------|
| `xingruyin` | 如音专属 | 技术/实现类 skill |
| `ziling` | 紫灵专属 | 需求/创意类 skill |
| `wensiyue` | 思月专属 | 文档/归档类 skill |
| `shared` | 共享 | 跨职能通用 skill |

### 5.4 category → owner 推断规则（初始填充用）

| category 前缀 | 推断 owner |
|--------------|-----------|
| `software-development` / `mlops` / `devops` / `github` / `gaming` | `xingruyin` |
| `productivity`（docs/powerpoint/note-taking相关） | `wensiyue` |
| `research`（需求/创意/ideation） | `ziling` |
| `autonomous-ai-agents` / `media` / `social-media` / `smart-home` / `red-teaming` | `shared` |

### 5.5 trigger_scenes 补充匹配时机

| 时机 | 动作 |
|------|------|
| 命中 skill 后 | 读取 metadata.owner → 分工校验 |
| 用户输入含中文 | 读取 metadata.trigger_scenes → L2 中文匹配 |
| skill 执行完成 | 更新 metadata.match_stats → 写回 SKILL.md |

## 六、分工防护机制

### 6.1 硬拦截规则

```
银月尝试直接调用 [非shared skill]
    │
    ▼
skill_view() 加载 SKILL.md → 读取 metadata.owner
    │
    ├── owner = shared → 允许调用
    │
    └── owner = 如音/紫灵/思月 → 直接拒绝
        │
        ▼
┌─────────────────────────────────────┐
│ ❌ 调用被拦截                         │
│─────────────────────────────────────│
│ [skill-name] 归属：如音专属           │
│ 不允许直接调用                        │
│                                     │
│ 请通过 delegate_task 委托如音执行     │
└─────────────────────────────────────┘
```

### 6.2 豁免机制

| 场景 | 有效期 | 说明 |
|------|--------|------|
| sub-agent 在线，审批通过 | 单次调用 | 记录在案，统计中 |
| sub-agent 离线/忙碌 | 单次调用 | 注明原因，不扣分 |
| 紧急情况（老大强指） | 单次调用 | 老大直接覆盖，记录audit.log |

### 6.3 豁免审批流程

```
银月尝试调用 [skill-name]
    │
    ▼
硬拦截触发
    │
    ├── sub-agent 在线 → 推送审批请求给 sub-agent
    │     │
    │     ▼
    │   sub-agent 收到飞书审批
    │   「银月申请调用 [skill-name]
    │    原因：[银月填写]
    │    [批准] [拒绝] [5分钟后自动批准]」
    │     │
    │     ▼
    │   批准 → 记录豁免 → 允许调用
    │   拒绝 → 拒绝调用
    │   超时 → 自动批准（计入统计）
    │
    └── sub-agent 离线/忙碌
          │
          ▼
        自动批准临时豁免（单次有效）
```

### 6.4 违规上报

- **实时上报**：每次拦截立即推送飞书给老大
- **每周巡检**：hermes-memory-maintenance cronjob 生成周报

## 七、sub-agent 信任积分机制

### 7.1 积分规则（仅针对 sub-agent）

| 操作 | 积分变化 |
|------|---------|
| 初始分 | 100 分 |
| 正常完成任务 | +0（维持） |
| 主动发现并修复 bug | +1 |
| 主动优化（性能/流程） | +1 |
| 任务超时/失败 | -2 |
| 主动绕过分工 | -10 |

> 下限：0 分（不会变负）

### 7.2 积分与权限联动

| 积分区间 | 权限状态 |
|----------|---------|
| ≥80 分 | 正常权限 |
| 60-79 分 | 高风险操作需审批（删除文件、跨分工操作、批量操作限流） |
| <60 分 | 所有关键操作需审批，调用频率限制（5次/分钟 → 2次/分钟） |

## 八、记忆变更工作流程

### 8.1 新增规范类记忆

```
1. 判定层级：
   - 临时性/一次性 → 写入当天 memories/ 日志
   - 永久性/通用性 → 写入 MEMORY.md
   - 高频复用/复杂流程 → 考虑提炼为 skill

2. 写入 MEMORY.md：
   - 确认当前字符数（目标 ≤1800）
   - 找到对应章节插入
   - 更新 "最后更新时间"

3. 若触发压缩（>1800字符）：
   - 优先清理 "遗留问题" 等临时章节
   - 精简长表述为列表
   - 确认压缩后 ≤1800
```

### 8.2 新增老大偏好类记忆

```
1. 写入 USER.md 对应章节
2. 若涉及分工边界变更 → 同步更新 shared/role-responsibility.md（银月操作）
3. 若涉及规范变更 → 在当天日志中记录，便于巡检时同步
```

### 8.3 新建 skill 流程

```
1. 创建 SKILL.md，编写 frontmatter（含标准字段）
2. 执行 metadata 初始化脚本（或手动添加）：
   - metadata.owner：按 category 推断
   - metadata.trigger_scenes：初始化为空列表（后续巡检补全）
   - metadata.match_stats：初始化为零值
3. 确认 owner 归属正确
4. 触发巡检：AI 自动提取 trigger_scenes 并回填
```

### 8.4 记忆删除/精简流程

```
1. 确认删除内容不在当前进行中的任务依赖范围内
2. 若是临时记录（临时变量、一次性决策）→ 直接删除
3. 若是永久规范 → 谨慎处理：
   - 确认该规范已被新的替代方案覆盖
   - 在日志中记录 "规范变更：XXX 已废弃"
4. 删除后检查 MEMORY.md 字符数
```

### 8.5 任务交接记忆流程

```
交出方（在交接前写入日志）：
1. 整理当前进度、关键信息、注意事项
2. 按 "任务交接日志格式" 写入当天 memories/ 日志
3. 确认交接内容完整性

接收方（在接收后）：
1. 从日志中读取交接信息
2. 确认接替者需要什么
3. 若有疑问，在日志中追问或直接沟通
```

## 九、验收标准速查

### 9.1 P0 前置条件

- [ ] 各 MEMORY.md ≤1800 字符
- [ ] 所有 SKILL.md 含 `metadata.owner`（非空）
- [ ] 所有 SKILL.md 含 `metadata.trigger_scenes`（可为空列表）
- [ ] `metadata.owner` 归属正确

### 9.2 P1 核心自动化

- [ ] 3条独立巡检 cron 创建成功（21:00）
- [ ] 次日各 memories/ 目录有巡检日志输出
- [ ] 各 MEMORY.md 含启动流程章节
- [ ] 各 MEMORY.md 含任务交接规范章节
- [ ] 各 MEMORY.md 含 Skill 索引摘要章节

### 9.3 P2 配套功能

- [ ] 调用非 shared skill 被硬拦截
- [ ] bypass.log 记录拦截事件
- [ ] 全局巡检 cron（03:00）创建成功
- [ ] 飞书审批 card 消息可正常收发
