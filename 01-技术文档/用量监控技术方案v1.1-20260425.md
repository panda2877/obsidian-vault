# Code Plan 用量监控技术方案

**文档名称**: 用量监控技术方案-20260426.md
**变更摘要**: 新增 Code Plan 额度监控功能，通过 cron + script 实现低于阈值时自动推送微信预警
**变更原因**: 避免因 MiniMax 额度耗尽影响正常开发工作
**关联需求**: 无（独立技术需求）
**编写者**: 幸如音
**日期**: 2026-04-26

---

## 1. 方案概述

Code Plan 用量监控是一个基于 Hermes Cron Job 的自动化预警系统。每 10 分钟触发一次，检查 MiniMax Code Plan 剩余额度，当任一模型用量低于阈值时，通过微信自动推送预警通知给老大。

## 2. 核心组件

| 组件 | 说明 |
|------|------|
| `code-plan-wakegate.py` | Python 脚本，负责调 MiniMax API 查询用量并判断是否触发预警 |
| Hermes Cron Job | 每 10 分钟触发一次 bash，执行上述脚本 |
| Hermes Delivery | 脚本输出通过 delivery 机制推送至微信 |

## 3. 阈值配置

| 阈值类型 | 当前值 | 说明 |
|----------|--------|------|
| 本周期阈值 | 50 | current_interval_usage_count 低于此值时触发 |
| 本周阈值 | 500 | current_weekly_usage_count 低于此值时触发 |
| 排除模型 | coding-plan-vlm, coding-plan-search | 不监控这两类模型 |

## 4. 核心逻辑

```
脚本执行
    ↓
调用 MiniMax API: GET /v1/api/openplatform/coding_plan/remains
    ↓
遍历 model_remains，对每个模型检测：
  - interval_rem < THRESHOLD_INTERVAL → 触发预警
  - weekly_rem < THRESHOLD_WEEKLY → 触发预警
    ↓
检测到阈值触发 且 用量较上次有变化
    ↓
输出纯文本预警消息
    ↓
Hermes Delivery 推送至微信
```

### 状态管理
- 使用 `~/.hermes/cron/.code_plan_wakegate_state.json` 记录上一周期的用量
- 仅当用量较上次发生变化时才触发预警（避免重复报警）
- 排除 vlm/search 两类不计费模型

## 5. Cron 触发流程

```
Hermes Cron (每10分钟)
    ↓
执行: python3 ~/.hermes/scripts/code-plan-wakegate.py
    ↓
无预警 → 输出 "wakeAgent=false" → 不推送
有预警 → 输出纯文本消息 → Hermes Delivery → 微信
```

## 6. 与 Hermes Delivery 的配合

- Cron Job 配置 `deliver: weixin`
- Script 直接输出纯文本消息（修复后不再输出 JSON）
- Delivery 机制将脚本 stdout 内容推送至微信
- 消息格式：`老大，MiniMax-M*本周期只剩XXX了，本周用量剩余XXX！请老大合理规划工作，注意token消耗。`

## 7. 消耗说明

| 场景 | 消耗 |
|------|------|
| 用量充足（不触发） | 仅脚本执行，无 MiniMax API 消耗 |
| 触发预警 | 1 次 MiniMax API 调用 + Hermes Delivery |

大部分时间零消耗，只有触发预警时才会计数。
