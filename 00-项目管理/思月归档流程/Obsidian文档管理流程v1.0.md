## 3. 归档流程

### 3.1 跨项目技术文档归档（如音 → 思月）

```
如音完成跨项目技术文档（如部署规范、技术标准等）
    ↓
提供变更摘要：
  - 文档名称
  - 变更摘要（一句话）
  - 变更原因
  - 关联项目/需求（如有）
    ↓
思月归档到 ~/obsidian-vault/00-项目管理/technical-docs/
    ↓
更新 technical-docs/CHANGELOG.md
    ↓
思月向银月汇报归档结果
```

> **注意**：需求文件夹内的技术文档（如 `TODO-001/技术方案.md`）走 3.2 需求文档归档流程，不在此处理。

### 3.2 需求文档归档（紫灵 → 思月）

```
紫灵完成需求文档
    ↓
提供变更摘要：
  - 需求编号
  - 需求名称
  - 变更摘要（一句话）
  - 变更原因
    ↓
思月在对应项目目录下创建 [需求编号-需求名称] 文件夹
    ↓
归档需求文档及关联文档
    ↓
更新项目 CHANGELOG.md
    ↓
思月向银月汇报归档结果
```

### 3.3 文档合并（宝子主动发起）

```
宝子说：「合并xxx需求文档」
    ↓
思月将需求文件夹下的文档合并到项目主文档
    ↓
在变更记录中新增：
  ## [版本] - [日期]（合并自《需求编号-需求名称》）
    ↓
更新项目 CHANGELOG.md
```

## 5. Obsidian 使用规范

1. **不要删除或移动 .obsidian 目录**（插件配置目录）
2. **大型二进制文件不要放入 Vault**（会导致 Git 仓库膨胀）
3. **手动 pull/push 同步**（PC/手机端每次编辑前先 pull，完成后 push）
4. **commit 信息格式**：`feat: [简短描述]` / `fix: [简短描述]`
5. **wikilink 使用**：Obsidian 支持 `[[文档名]]` 链接，推荐使用
