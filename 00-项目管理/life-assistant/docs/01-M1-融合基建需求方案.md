## 📌 一、背景与目标

### 业务背景
老大需要一个跨平台（手机 H5 + 网页）的生活助手应用，涵盖记账、待办等日常功能。现有 Hermes Dashboard 面板系统已具备完整的看板、统计、Agent、仓库等功能模块。现决定重构现有系统，让**生活助手作为主框架**，现有功能模块逐步迁移为附属模块。

### 核心目标
1. **生活助手作为主框架** — 重构现有项目，生活助手首页为默认入口
2. **现有功能逐步迁移** — 看板、统计、Agent、仓库等作为附属模块，渐进式迁移
3. **自适应导航架构** — 桌面端左侧侧边栏（全功能），移动端底部Tab（生活化 + 可编辑）
4. **云端同步** — 所有数据通过 API 操作，手机端 H5 实时访问
5. **便捷鉴权** — 单用户 + 长效 JWT Token 绑定设备

### 成功标准
- [ ] 重构后所有现有功能（看板、统计、Agent、仓库）正常可用
- [ ] 生活助手首页为默认入口

- [ ] 移动端底部Tab固定5个：首页/记账/统计/看板/更多（不可编辑）

- [ ] 所有生活助手数据通过 API 操作，云端持久化

### 使用场景

## 🔀 四、业务流程

### M1 主流程

```
用户打开手机 H5 / 网页端
    ↓
检测是否有已绑定的 Token
    ├─ 有 → 自动登录 → 进入生活助手首页
    └─ 无 → 显示绑定页面（输入 Token）
              ↓
        服务端验证 Token → 绑定设备标识
              ↓
        生成设备会话 → 进入生活助手首页
    ↓
桌面端：左侧侧边栏（生活/管理两组）
    ↓
移动端：底部Tab（默认：🏠首页 💰记账 📋待办 📊统计 🗂️看板 ⚙️更多）
    ↓
点击各Tab → SPA 式切换页面（保留状态）
    ↓
生活首页操作（记账/待办）→ API 调用 → 云端持久化
```

## 💾 五、数据概念

### 核心实体

#### 设备绑定表（device_bindings）
- `id` INTEGER — 主键（自增）
- `token_hash` TEXT — LIFE_TOKEN 的 SHA-256 哈希
- `device_id` TEXT — 设备唯一标识（前端生成 UUID）
- `device_name` TEXT — 设备名称（可选）
- `last_login_at` TEXT — 最后登录时间
- `created_at` TEXT — 绑定时间
- `updated_at` TEXT — 更新时间

#### 记账表（finance_records）
- `id` INTEGER — 主键（自增）
- `type` TEXT — 收支类型：income/expense
- `amount` REAL — 金额（正数）
- `category_id` INTEGER — 分类ID（外键）
- `note` TEXT — 备注
- `record_date` TEXT — 记账日期（YYYY-MM-DD）
- `created_at` TEXT — 创建时间
- `updated_at` TEXT — 更新时间

#### 分类表（finance_categories）
- `id` INTEGER — 主键（自增）
- `name` TEXT — 分类名称
- `type` TEXT — 收支类型：income/expense
- `icon` TEXT — Emoji 图标
- `sort_order` INTEGER — 排序序号

#### 待办表（todo_tasks）
- `id` INTEGER — 主键（自增）
- `title` TEXT — 任务标题
- `description` TEXT — 详细描述
- `category` TEXT — 分类标签
- `priority` TEXT — 优先级：low/medium/high/urgent
- `status` TEXT — 状态：pending/in_progress/done/cancelled
- `due_date` TEXT — 截止日期（可选）
- `created_at` TEXT — 创建时间
- `updated_at` TEXT — 更新时间

### 数据关系
- 单用户模式，所有表无需 user_id 字段
- `finance_categories` 1:N `finance_records`（一个分类多条记账）

### 系统预设分类
**支出（10个）**：餐饮🍜、交通🚗、购物🛒、住房🏠、娱乐🎮、医疗💊、教育📚、通讯📱、服饰👔、其他支出📦
**收入（6个）**：工资💰、奖金🏆、兼职💼、理财📈、红包🧧、其他收入📦

## 📎 七、技术约束

### 复用现有架构
- **前端框架**: uni-app (Vue3 + TS + Pinia + uView UI 2.x)
- **后端框架**: Express + Node.js（BFF 模式）
- **数据库**: SQLite（与看板共用 `kanban.db`，sql.js WASM 驱动）
- **认证**: 长效 JWT Token（自实现，非微信登录）
- **部署**: PM2
- **导航**: 自定义底部导航组件（替代原生 TabBar）

### 新增部分
- **前端**: `src/components/CustomTabBar.vue`（自定义导航）、`src/modules/life/`（生活模块）
- **后端**: `backend/middleware/lifeAuth.js`（鉴权中间件）、`backend/services/lifeDb.js`（数据库服务）
- **数据库**: 新增 `finance_records`、`finance_categories`、`todo_tasks`、`device_bindings` 表
- **配置**: 新增环境变量 `LIFE_TOKEN`（长效 Token）

### 迁移策略
- 现有页面（看板/统计/Agent/仓库）**代码不动**，仅调整目录位置
- 后端路由**完全不动**，保持现有 `/api/*` 路由结构
- 分阶段迁移：导航重构 → 生活首页 → 模块整理
