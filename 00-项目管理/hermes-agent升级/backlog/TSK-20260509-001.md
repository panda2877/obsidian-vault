## 笔记

### 2026-05-09 前期调研结论：子代理调用链能力评估

> 来源：银月调研整理 — 基于 Hermes v0.13 `delegate_task` 机制的四项需求逐条分析

#### 需求①：自动分解和编排任务 ⚡半自动

- `delegate_task` 提供并行/串行子任务基础能力（`tasks` 数组），但「自动分解」无内置引擎
- 当前靠父 Agent LLM 推理拆解任务，编排逻辑需手写 skill 或代码
- 可写 `task-orchestrator` skill 让父 Agent 按固定策略分解

#### 需求②：根据任务内容选 profile + memory 分片 + skill 🛠手动可做

- `delegate_task` 子 Agent 是**轻量级克隆** — 共享父进程配置，不加载独立 profile，不自动选 skill
- 父 Agent 通过 `context` 传递 soul 定义，通过 toolsets 限制工具
- ❌ **不存在**任务内容 → soul/memory/skill 的自动映射引擎
- ❌ 子 Agent 无独立 memory，不自动加载 skill（需 context 传递角色定义后手动 `skill_view`）
- Profile 多进程模式有独立记忆和 skill，但非「用完即走」的临时子代理

#### 需求③：子代理操作过程对用户可见 ❌最大Gap

- `delegate_task` 设计哲学：**「只看结果，不看过程」**
- 中间 tool call、思考链、错误尝试均不可见，父 Agent 和用户都看不到
- 无法及时指出问题（同步阻塞）
- 💡 替代方案：Profile 多进程模式（如音/思月作为独立 Agent 跑飞书），代价是生命周期不再是「用完即走」

#### 需求④：用后自动释放 + 父代理总结写回 ✅部分支持

- **自动释放** ✅ 原生支持，子 Agent 返回后自动销毁
- **写回机制** ❌ 子 Agent 返回的是自报告（self-report），不一定准确
- **写入 soul 和 memory** ✅ 父 Agent 可调用 `memory`/`skill_manage` 工具，需写标准流程 skill

#### 总体结论

| 需求 | 原生支持度 | 定制量 |
|------|-----------|--------|
| ① 自动分解编排 | ⚡ 半自动 | 写编排 skill |
| ② 选 soul+skill+memory | 🛠 手动可做 | 写 context 映射逻辑 |
| ③ 过程对用户可见 | ❌ 不支持 | 换 Profile 模式或自研 |
| ④ 释放+写回总结 | ✅ 部分支持 | 写总结回写 skill |

**核心结论：** Hermes 提供了优秀的构建块（delegate_task、Profiles、memory、skills），但无开箱即用的「自动多 Agent 编排框架」。

#### 推荐路线

最接近愿景的组合：**父 Agent（编排者）+ Kanban（异步工作流编排）+ Profile 多进程（独立 soul+memory）**，而非 `delegate_task`。

### 2026-05-09 源码分析：delegate_task 逐项可行性

> 来源：银月源码分析 — 基于 `delegate_tool.py` 关键行号

#### 需求①：父 Agent 先讨论分解再编排 ✅原生支持

- `delegate_task` 支持两种模式：单任务（`goal`）和批量并行（`tasks` 数组）
- 可在飞书上先讨论分解方案，然后父 Agent 一次性 `delegate_task(tasks=[...])` 并行派发
- **不需要改任何源码**

#### 需求②：子代理自动选 profile + skill + memory ⚡可做

**源码现状**（`delegate_tool.py` 第1086-1116行）：
```python
child = AIAgent(
    skip_context_files=True,    # ❌ 不加载 profile/AGENTS.md
    skip_memory=True,           # ❌ 不加载 memory
    ephemeral_system_prompt=child_prompt,  # 只通过 context 传提示
    session_db=getattr(parent_agent, "_session_db", None),  # 共享 DB
)
```
子 Agent 人格完全由父 Agent 在 `context` 参数里手工写。

**改造点（轻量）：**

| 目标 | 改哪里 | 难度 |
|------|--------|------|
| context 自动选 skill | `_build_child_agent()` 根据 `goal` 关键词匹配 skill 列表，注入 `child_prompt` | ⭐ 几行代码 |
| 子 Agent 加载 memory 分片 | `skip_memory=False` + `memory_tag` 参数，只加载特定标签 memory | ⭐⭐ |
| 按 profile 运行 | 当前不支持，需传 `profile_name` 走独立配置 | ⭐⭐⭐ |

**最现实改造路径**：在 `delegate_task` 参数中加 `skills` + `soul_prompt` 字段，子 Agent 启动时自动 `skill_view()` + 注入人格定义，不动 AIAgent 核心。

#### 需求③：子代理过程对用户可见 ⚡可改造

**三个突破口：**

**突破口 1：tool_trace 已收集**（`_run_single_child()` 第1614-1648行）
- 子 Agent 的 tool trace 已被遍历收集（工具名、参数大小、结果大小、成功/失败状态）
- **当前只被 TUI 消费，不返回给父 Agent**
- 改造：把 `tool_trace` + `reasoning` 加入返回的 `entry`，父 Agent 即可看到完整操作链

**突破口 2：thinking_callback 已传入**（第1107行）
- 子 Agent 思考过程已有回调机制，默认不展示

**突破口 3：session DB 实际上在记录**
- 子 Agent 共享父进程 `session_db`，`_flush_messages_to_session_db()`（`run_agent.py` 第4001行）会把子 Agent 的**每一条消息（含 tool call、思考链、结果）写入 SQLite**
- 只是用父 session_id 写入，`session_search` 查不到

**三个改造方案：**

| 方案 | 工作量 | 效果 |
|------|--------|------|
| **A. 返回 tool_trace + reasoning** ✅推荐 | ⭐ 改 `_run_single_child()` ~10行 | 父 Agent 拿到完整工具调用链，可转发给用户 |
| B. 子 Agent 独立 session | ⭐⭐ 分配独立 session_id | 完整对话写入 SQLite，可 session_search 回溯 |
| C. Profile 模式（不改代码） | 0 | 子 Agent 以独立 Profile 跑飞书，用户直接看到全部过程 |

#### 需求④：用后自动释放 + 总结写回 ✅部分支持

**自动释放** ✅ 原生支持（第1864-1867行）：
```python
try:
    if hasattr(child, "close"):
        child.close()
except Exception:
    logger.debug("Failed to close child agent after delegation")
```

**总结写回** ⚡ 两种做法：

**做法一（不改代码，纯 skill 规范）：** 写 `subagent-postmortem` skill，规范父 Agent 收到结果后：
1. 检查 `tool_trace` 中的 error 条目
2. 有错误 → `memory(action='add', content='...')`
3. 有值得保存的流程 → `skill_manage(action='create', ...)`

**做法二（改 delegate_tool.py，自动触发）：** 在返回逻辑后加 `on_complete` 回调钩子，约20行代码。

#### 总表：理想 vs 现实

| 需求 | 当前状态 | 改造成本 |
|------|---------|---------|
| ① 父 Agent 分解后编排 | ✅ 原生支持 | 0 |
| ② 子 Agent 自动选 soul+skill+memory | ⚡ 可做 | 加 `skills` + `soul_prompt` 参数（~50行） |
| ③ 过程对用户可见 | ⚡ tool_trace 已收集，需透出 | 改 `_run_single_child()` 返回 tool_trace（~10行） |
| ④ 释放 + 总结写回 | ✅ 释放原生 \| ⚡ 写回需 skill 规范 | 写一个 postmortem skill |
