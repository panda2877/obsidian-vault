## 笔记

### 合并 v0.13 对自我实现功能的影响分析

> 以下分析基于 v0.13 Release Notes 中与我们有冲突/重叠的功能点，结合当前 4 个保留的源码改动逐项判断。

#### 影响项 1：prompt_builder.py — LanceDB SOUL.md 加载

| 维度 | 内容 |
|------|------|
| **文件** | `agent/prompt_builder.py` |
| **v0.13 风险** | 该文件上游有 82 个 commit，存在冲突修改风险 |
| **影响** | 上游可能修改了 `load_soul_md()` 或周边函数，merge 时可能冲突。但 v0.13 没有 SOUL.md 相关的新功能公告，我们的 LanceDB 集成是独有逻辑 |
| **处理方式** | merge 时需手动处理冲突，保留 LanceDB 读取逻辑 |

#### 影响项 2：memory_tool.py — LanceDB 记忆加载

| 维度 | 内容 |
|------|------|
| **文件** | `tools/memory_tool.py` |
| **v0.13 风险** | 上游有 22 个 commit |
| **影响** | v0.13 新增了 `transform_llm_output` 插件 hook 和 `X-Hermes-Session-Key` 会话记忆功能，但这些是新加功能，不影响 `MemoryStore.load_from_disk()`。冲突概率较低 |
| **处理方式** | merge 时检查 `load_from_disk()` 是否被上游修改，保留 LanceDB 逻辑 |

#### 影响项 3：kanban_db.py — agent_registry 表

| 维度 | 内容 |
|------|------|
| **文件** | `hermes_cli/kanban_db.py` |
| **v0.13 风险** | 🟡 **中风险** — 上游 kanban_db.py 完全重写（多 board 架构），但 **没有 agent_registry 表** |
| **具体发现** | v0.13 的 kanban 用完全不同的方式追踪 agent：`list_profiles_on_disk()` 扫描文件系统发现 profile，`task_runs` 表按 run 记录谁执行了什么，`claim_lock`/`claim_expires` 做任务级别锁。没有持久化的 agent 注册机制 |
| **影响** | 我们的 `agent_registry` 表提供了 v0.13 没有的能力：持久化的 agent 身份、角色、能力声明、状态追踪。两者不冲突，可以共存 |
| **处理方式** | 将 `agent_registry` 表 + CRUD 函数移植到 v0.13 的新 `kanban_db.py` 中。v0.13 的 schema 和函数结构不同，需要重新适配代码位置 |

#### 影响项 4：snapshot plugin + tasks_store

| 维度 | 内容 |
|------|------|
| **文件** | `plugins/memory/snapshot/tasks_store.py` |
| **v0.13 风险** | 文件是我们新增的，上游不存在，无冲突风险 |
| **影响** | v0.13 的 Checkpoints v2 是全新的状态持久化系统（单 store、真实剪枝、磁盘保护）。与我们的 tasks_store 功能重叠：都做任务状态追踪 |
| **处理方式** | 评估 Checkpoints v2 是否覆盖我们的需求。如果覆盖，将 tasks_store 的数据迁移到 Checkpoints v2 后删除该 plugin |

#### 影响项 5：已还原的文件（无冲突风险）

| 文件 | 说明 |
|------|------|
| `api_server.py` | 已还原为 origin/main 一致，merge 无冲突 |
| `base.py` | 同上 |
| `weixin.py` | 同上 |
| `run.py` | 同上 |
| `send_message_tool.py` | 同上 |
| `skills_tool.py` | 已删除 owner-lock 代码，当前与 origin/main 一致 |

#### 影响项 6：配置/环境功能（无影响）

LiteLLM Proxy、LanceDB 记忆系统、Dashboard BFF、Code Plan 监控、Profile 架构、Obsidian 看板同步、Cron Job 体系 — 这些都不在 Hermes 源码仓库内，升级代码不会影响它们。

#### 总结

| 优先级 | 文件 | 风险等级 | 处理方式 |
|--------|------|---------|---------|
| 🔴 P0 | `kanban_db.py` | 中 — schema 兼容，但 v0.13 无 agent_registry | 直接移植到 v0.13 的新 schema 中 |
| 🟡 P1 | `prompt_builder.py` | 中 — 代码冲突 | merge 时手动处理，保留 LanceDB |
| 🟡 P1 | `memory_tool.py` | 中 — 代码冲突 | merge 时检查上游修改 |
| 🟢 P2 | snapshot plugin | 低 — 功能重叠 | 评估 Checkpoints v2，决定是否迁移 |
| 🟢 无 | 已还原文件 | 无 | 无需处理 |
| 🟢 无 | 配置/环境功能 | 无 | 无需处理 |
