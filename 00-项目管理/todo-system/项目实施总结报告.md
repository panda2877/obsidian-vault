## 一、项目实施规律

### 1.1 技术类任务的标准执行流程

```
┌─────────────────────────────────────────────────────────────┐
│ 阶段1: 环境预检 → 阶段2: 依赖验证 → 阶段3: 部署实施 → 阶段4: 验证交付 │
└─────────────────────────────────────────────────────────────┘
```

| 阶段 | 关键动作 | 产出物 |
|------|----------|--------|
| **环境预检** | 检查Java、MySQL、Git等基础工具 | 环境清单 |
| **依赖验证** | 验证Maven/Gradle、数据库连接、端口占用 | 依赖报告 |
| **部署实施** | 代码拉取→数据库初始化→应用构建→服务启动 | 运行服务 |
| **验证交付** | 接口测试→功能验证→文档归档 | 验收确认 |

### 1.2 各阶段常见问题及应对

| 阶段 | 常见问题 | 应对策略 |
|------|----------|----------|
| **环境预检** | 工具未安装/版本不兼容 | 先输出版本命令摸底，再针对性安装 |
| **依赖验证** | Maven Wrapper缺失、数据库密码错误 | 检查`.mvn/`目录、验证配置文件 |
| **部署实施** | 端口被占用、数据库表已存在 | `lsof -i:端口`查进程、`DROP TABLE`清理 |
| **验证交付** | API返回500但无日志 | 查看`target/spring.log`或应用日志 |

### 1.3 环境依赖检查顺序

```
1. 系统工具: java -version, git --version, mysql --version
2. 构建工具: ./mvnw -v (Maven Wrapper)
3. 数据库服务: systemctl status mysql / mysql -u root -p
4. 端口可用性: lsof -i:8080
5. 磁盘空间: df -h (确保target目录有足够空间)
```

## 二、协作模式优化建议

### 2.1 角色协作流程

```
银月(调度)
    │
    ├──→ 紫灵(需求) ──→ 输出需求文件夹（如 TODO-001-xxx/）
    │
    ├──→ 如音(技术) ──→ 执行实施
    │
    └──→ 文思月(文档) ──→ 归档文档
```

**需求文件夹概念：**
每个需求对应一个独立文件夹（如 `TODO-001-父子任务与进度管理/`），包含该需求的完整文档集：
- 需求文档
- 技术设计方案
- 部署方案
- 用户手册等

**优化建议：**
- **任务派发**：银月→如音时，应同步传递需求文件夹链接，而非口头描述
- **文档前置**：文思月应在实施前完成文档初稿，避免边做边写
- **变更同步**：需求变更必须走文档更新流程，不能只靠口头通知

### 2.2 文档归档时机

| 文档类型 | 归档时间点 | 说明 |
|----------|------------|------|
| 需求文件夹 | 任务开始前 | 紫灵确认后归档（包含需求文档、技术设计、部署方案等） |
| 技术设计 | 评审通过后 | 如音确认方案后归档 |
| 部署方案 | 首次部署完成验证后 | 确认步骤正确后归档 |
| 对接文档 | 接口联调完成后 | 柳如烟可调用后归档 |

**当前问题**：部分文档在任务完成后才归档，导致执行者无参考依据。

### 2.3 文档组织规范

项目文档采用分层结构：

```
docs-archive/todo-system/
├── CHANGELOG.md              ← 项目级变更记录
├── 需求文档v1.0.md            ← 项目级文档（通用设计）
├── 技术设计方案v1.0.md        ← 项目级文档
├── 部署方案v1.0.md            ← 项目级文档
├── 银月对接文档v1.0.md        ← 用户手册
├── 项目实施总结报告.md         ← 项目级文档
└── TODO-001-xxx/             ← 需求文件夹（按需创建）
    └── 需求文档v1.0-xxx.md    ← 该需求的专项需求文档
```

**规则：**
- 项目级文档放在根目录
- 各需求的专项文档放在对应的需求文件夹中
- 用户手册（如银月对接文档）放在根目录

## 四、其他规律与经验

### 4.1 项目执行中的关键检查点

| 接口可用性 | `curl localhost:8080/todo/list` | 返回JSON |

### 4.2 常见陷阱及规避

1. **配置优先级混乱**：Spring Boot的`application-prod.properties`可能不会自动生效，需明确使用`-Pprod`或`--spring.profiles.active=prod`

2. **数据库表已存在**：重新部署时应先检查`SHOW TABLES`，避免`CREATE TABLE`报错

3. **端口占用**：旧进程未关闭导致启动失败，`pkill -f spring-boot`可清理

4. **Git分支搞错**：默认分支可能是`main`而非`master`，部署前确认

### 4.3 知识复用建议

- **CLAUDE.md**：项目根目录的构建说明应保持更新，新任务执行者可快速上手
- **归档文档**：每次任务完成后应更新`CHANGELOG.md`，便于追溯
- **标准化流程**：将部署步骤抽象为可复用的checklist，减少每次重新摸索

### 4.4 反馈机制

| 场景 | 反馈内容 | 反馈对象 |
|------|----------|----------|
| 环境缺失 | 缺少XX工具/版本不兼容 | 银月（协调安装） |
| 文档错误 | XX文档与实际不符 | 文思月（修正文档） |
| 需求不清 | XX需求描述模糊 | 紫灵（补充澄清） |
| 技术方案 | XX方案有更优解 | 银月（协调评审） |
