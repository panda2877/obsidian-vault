## 一、项目概述

### 1.1 项目背景

现有待办事项系统仅支持扁平化的待办列表管理，无法表达父子任务层级关系，也无法追踪项目整体进度。为满足项目管理和任务拆解的需求，需要在现有系统基础上扩展父子任务层级、项目进度计算等功能。

### 1.2 项目目标

1. 支持父子任务层级结构，实现任务的拆解与聚合
2. 支持两种顶级任务形态：可包含子任务的父任务、直接挂载的未挂靠任务
3. 提供树形接口展示任务全貌
4. 支持项目进度自动计算（基于子任务权重）
5. 保证现有接口 `/todo/list` 稳定不变

### 1.3 核心定位

不做前端页面，待办的录入、提醒、状态更新全部由AI助手（柳如烟）接管。

## 二、数据库表结构设计

### 2.1 表结构

```sql
CREATE TABLE `todo` (
    `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '任务唯一标识',
    `title`         VARCHAR(255)    NOT NULL DEFAULT '' COMMENT '任务标题',
    `content`       TEXT                   DEFAULT NULL COMMENT '任务详细描述',
    `deadline`      DATETIME               DEFAULT NULL COMMENT '截止时间',
    `status`        TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '状态: 1=pending(未完成), 2=done(已完成)',
    `parent_id`     BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '父任务ID, 0表示顶级任务',
    `priority`      INT             NOT NULL DEFAULT 0 COMMENT '优先级, 数值越大优先级越高',
    `weight`        INT             NOT NULL DEFAULT 1 COMMENT '权重, 仅子待办有效',
    `progress`      TINYINT UNSIGNED        DEFAULT NULL COMMENT '项目进度(0-100), 仅父任务有效',
    `created_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `updated_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    INDEX `idx_parent_id` (`parent_id`),
    INDEX `idx_status` (`status`),
    INDEX `idx_deadline` (`deadline`),
    INDEX `idx_parent_status` (`parent_id`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='待办事项表';
```

## 三、接口规范

### 3.1 `/todo/add` - 新增待办

#### 请求格式

```
POST /todo/add
Content-Type: application/json
```

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| title | string | 是 | - | 任务标题（最大255字符） |
| content | string | 否 | null | 任务详细描述 |
| deadline | string | 否 | null | 截止时间，格式: YYYY-MM-DD HH:mm:ss |
| parent_id | int | 否 | 0 | 父任务ID，0表示顶级任务 |
| priority | int | 否 | 0 | 优先级，数值越大优先级越高 |
| weight | int | 否 | 1 | 权重，仅子待办有效 |

**请求示例：**

```json
{
    "title": "项目A",
    "content": "这是一个父任务",
    "deadline": "2026-05-01 12:00:00",
    "parent_id": 0,
    "priority": 5,
    "weight": 1
}
```

#### 响应格式

```json
{
    "code": 0,
    "message": "success",
    "data": {
        "id": 1,
        "title": "项目A",
        "content": "这是一个父任务",
        "deadline": "2026-05-01 12:00:00",
        "status": 1,
        "parent_id": 0,
        "priority": 5,
        "weight": 1,
        "progress": null,
        "created_at": "2026-04-26 20:00:00",
        "updated_at": "2026-04-26 20:00:00"
    }
}
```

#### 业务规则

1. `parent_id = 0`：创建顶级任务（父任务或未挂靠任务）
2. `parent_id > 0`：创建子待办，隶属于指定的父任务
3. 子待办的 `weight` 默认值为 1，用于进度计算
4. `parent_id` 不能等于自身 `id`（禁止循环引用）
5. 若指定的 `parent_id` 不存在，返回错误

#### 错误码

| 错误码 | 错误信息 | 说明 |
|--------|----------|------|
| 0 | success | 成功 |
| 1001 | title cannot be empty | 标题不能为空 |
| 1002 | parent_id does not exist | 指定的父任务不存在 |
| 1003 | cannot create child task under child task | 子待办不可再创建子任务 |
| 1004 | invalid parent_id (circular reference) | 循环引用禁止 |
| 1005 | title too long (max 255 chars) | 标题过长 |

## 四、核心逻辑说明

### 4.1 树形结构构建算法

```
算法: BuildTodoTree
输入: 所有任务列表 (List<Todo>)
输出: 树形结构 (TreeNode)

1. 创建虚拟根节点 root = { id: 0, title: "待办事项", children: [] }

2. 将所有任务按 parent_id 分组:
   - parent_id = 0 的任务归为顶级任务列表 topLevelTasks
   - parent_id > 0 的任务归为子任务映射 childMap (key: parent_id, value: [children])

3. 遍历 topLevelTasks:
   - 若任务在 childMap 中存在子任务，则创建 TreeNode 并挂载子节点
   - 若任务在 childMap 中不存在子任务，则创建 TreeNode 并设置空 children

4. 将所有顶级节点加入 root.children

5. 返回 root
```

**伪代码实现：**

```python
def build_todo_tree(todos):
    # 创建虚拟根节点
    root = TreeNode(id=0, title="待办事项")
    
    # 按 parent_id 分组
    child_map = defaultdict(list)
    top_level_tasks = []
    
    for todo in todos:
        if todo.parent_id == 0:
            top_level_tasks.append(todo)
        else:
            child_map[todo.parent_id].append(todo)
    
    # 递归构建子树
    def build_node(todo):
        node = TreeNode(**todo.__dict__)
        node.children = [build_node(child) for child in child_map.get(todo.id, [])]
        return node
    
    # 构建所有顶级节点
    root.children = [build_node(task) for task in top_level_tasks]
    
    return root
```

### 4.2 进度计算逻辑

```
公式: progress = Σ已完成子任务权重 / Σ子任务总权重 × 100%

计算规则:
1. 仅父任务需要计算进度
2. 仅统计直接子待办（parent_id = 父任务id）
3. 跳过 weight = 0 的子任务
4. 若无子任务或所有子任务权重为0，返回 null 或 0

算法: CalculateProgress
输入: 子任务列表 (List<Todo>)
输出: 进度百分比 (int)

1. total_weight = Σ(子任务.weight)，跳过 weight = 0
2. done_weight = Σ(子任务.weight)，条件: status = done 且 weight > 0
3. 若 total_weight = 0，返回 null
4. progress = (done_weight / total_weight) × 100，向下取整
5. 返回 progress
```

**伪代码实现：**

```python
def calculate_progress(sub_tasks):
    total_weight = 0
    done_weight = 0
    
    for task in sub_tasks:
        if task.weight > 0:
            total_weight += task.weight
            if task.status == 2:  # done
                done_weight += task.weight
    
    if total_weight == 0:
        return None
    
    return int((done_weight / total_weight) * 100)
```

### 4.3 级联删除逻辑

```
算法: CascadeDelete
输入: 待删除任务ID (id)
输出: 删除结果

1. 查询任务信息，确认任务存在

2. 若 id = 0（根节点），返回错误: 禁止删除根节点

3. 判断任务类型:
   - 若 parent_id = 0 且存在子任务: 父任务
   - 若 parent_id = 0 且不存在子任务: 未挂靠任务
   - 若 parent_id > 0: 子待办

4. 开启事务:
   - 若为父任务:
     a. 查询所有 parent_id = id 的子任务
     b. 删除所有子任务
     c. 删除父任务
   - 若为未挂靠任务或子待办:
     a. 直接删除任务
   
5. 若删除的是子待办，重新计算其父任务的进度

6. 提交事务
```

**SQL 实现：**

```sql
-- 删除父任务及其所有子任务（原子操作）
START TRANSACTION;

-- 1. 删除所有子任务
DELETE FROM todo WHERE parent_id = ?;

-- 2. 删除父任务
DELETE FROM todo WHERE id = ?;

COMMIT;
```
