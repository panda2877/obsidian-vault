## 一、项目概述

### 1.1 项目背景

现有待办事项系统仅支持扁平化的待办列表管理，无法表达父子任务层级关系，也无法追踪项目整体进度。为满足项目管理和任务拆解的需求，需要在现有系统基础上扩展父子任务层级、项目进度计算等功能。

### 1.2 项目目标

1. 支持父子任务层级结构，实现任务的拆解与聚合
2. 支持两种顶级任务形态：可包含子任务的父任务、直接挂载的未挂靠任务
3. 提供树形接口展示任务全貌
4. 支持项目进度自动计算（基于子任务权重）
5. 保证现有接口 `/todo/list` 稳定不变

### 1.3 核心定位

不做前端页面，待办的录入、提醒、状态更新全部由AI助手（柳如烟）接管。

## 二、技术架构决策

### 2.1 单表方案

父子任务使用同一张表存储，通过 `parent_id` 字段建立关联关系。

### 2.2 父子任务关系设计

通过 `parent_id` 字段标识父子关系，区分三种任务形态：

| 术语 | 说明 |
|------|------|
| **父任务** | `parent_id = 0`，有子任务，是子待办的上级节点 |
| **未挂靠任务** | `parent_id = 0`，无子任务，不属于任何父任务，直接挂在虚拟根节点下 |
| **子待办** | `parent_id > 0`，隶属于某个父任务 |

**关系规则：**
- `parent_id = 0`：顶级任务（父任务或未挂靠任务）
- `parent_id > 0`：该任务是子待办，其 parent_id 的值 = 父任务的 ID

**树形结构示意图：**

```
id=0 (虚拟根节点 "待办事项")
├── id=1 (父任务: 项目A, parent_id=0, 有子任务)
│   ├── id=3 (子待办: 子任务A-1, parent_id=1, weight=2, status=done)
│   ├── id=4 (子待办: 子任务A-2, parent_id=1, weight=3, status=pending)
│   └── id=5 (子待办: 子任务A-3, parent_id=1, weight=1, status=done)
├── id=2 (父任务: 项目B, parent_id=0, 有子任务)
│   └── id=6 (子待办: 子任务B-1, parent_id=2, weight=1, status=pending)
├── id=7 (未挂靠任务: 临时待办, parent_id=0, 无子任务)
└── id=8 (未挂靠任务: 单次提醒, parent_id=0, 无子任务)
```

**关键区别：**
- 父任务和未挂靠任务都是 `parent_id = 0`，区别在于是否有子任务
- 未挂靠任务是独立的顶级任务，不参与任何层级的构建
- 删除父任务时会级联删除所有子待办；删除未挂靠任务直接删除单条记录

## 三、功能需求

### 3.1 父子任务层级（Feature 01）

#### 3.1.1 字段扩展

在现有待办基础上，新增以下字段：

| 字段名 | 默认值 | 业务含义 |
|--------|--------|----------|
| `parent_id` | 0 | 父任务 ID，0 表示顶级任务 |
| `priority` | 0 | 优先级，数值越大优先级越高，父子任务均可设置 |
| `weight` | 1 | 权重，仅子待办有效，用于进度计算 |
| `progress` | null | 项目进度(%)，仅父任务有效 |

#### 3.1.2 父子任务规则

1. **创建规则**
   - 创建时指定 `parent_id = 0` → 创建顶级任务（父任务或未挂靠任务）
   - 创建时指定 `parent_id > 0` → 创建该任务的子待办
   - 子待办不可再创建自己的子任务（层级限制为 2 层：父任务 → 子待办）

2. **删除规则**
   - 删除父任务时，**同步删除所有子待办**
   - 删除未挂靠任务时，直接删除单条记录
   - 删除操作保证原子性，确保数据一致性

3. **查询规则**
   - `/todo/list`：返回所有任务（扁平列表），不展示层级
   - `/todo/tree`：返回树形结构，根节点展示虚拟根节点「待办事项」

#### 3.1.3 虚拟根节点

树形接口中始终展示一个虚拟的默认根节点：
- id 固定为 0
- title 固定为「待办事项」
- 不存储在数据库中，不可操作

### 3.2 树形接口（Feature 02）

#### 3.2.1 业务行为描述

新增 `/todo/tree` 接口，以树形结构返回所有任务。

**语义约束：**
- 根节点 id=0 为虚拟节点，不可操作
- 子任务不可创建自己的子任务（层级限制为 2 层）
- 若没有任何任务，返回默认根节点及其空 children 数组

#### 3.2.2 接口约束

1. **不动现有接口**：不修改 `/todo/list`，保持向后兼容
2. **空树处理**：若没有任何任务，返回默认根节点（id=0）及其空 children 数组

### 3.3 项目进度管理（Feature 03）

#### 3.3.1 进度计算规则

项目进度基于子任务权重计算：

```
项目进度（progress）= Σ已完成子任务权重 / Σ子任务总权重 × 100%
```

**计算示例：**

```
子任务列表：
- 子任务1: weight=2, status=done
- 子任务2: weight=3, status=pending
- 子任务3: weight=1, status=done

progress = (2 + 1) / (2 + 3 + 1) × 100% = 3/6 × 100% = 50%
```

#### 3.3.2 进度字段存储策略

进度可采用以下任一策略，或两者结合：

| 策略 | 说明 |
|------|------|
| 实时计算 | 查询时实时计算，数据准确 |
| 存储在父任务记录 | 查询性能高，但需在子任务变更时同步更新 |

#### 3.3.3 进度边界情况

- 无子任务时：progress 返回 null 或 0
- 所有子任务权重为 0 时：progress 返回 0
- 权重为 0 的子任务：进度计算时跳过

### 3.4 优先级管理（Feature 04）

#### 3.4.1 优先级规则

- 父子任务都可以设置优先级
- 优先级为整数，数值越大优先级越高
- 默认值为 0
- 优先级影响任务排序（可选扩展）

## 四、数据概念

### 4.1 任务字段说明

每个任务包含以下字段及其业务含义：

| 字段名 | 业务含义 |
|--------|----------|
| `id` | 任务唯一标识 |
| `title` | 任务标题，简短描述 |
| `content` | 任务详细描述/内容 |
| `deadline` | 截止时间 |
| `status` | 状态：pending（未完成）/ done（已完成） |
| `parent_id` | 父任务 ID，0 表示顶级任务 |
| `priority` | 优先级，数值越大优先级越高 |
| `weight` | 权重，仅子待办有效，用于进度计算 |
| `progress` | 项目进度百分比，仅父任务有效 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

### 4.2 层级关系

| 类型 | parent_id | 说明 |
|------|------------|------|
| 父任务 | 0 | 有子任务的任务 |
| 未挂靠任务 | 0 | 无子任务的顶级任务 |
| 子待办 | > 0 | 隶属于某个父任务 |
| 虚拟根节点 | null | id=0，标题固定为「待办事项」，不存储在数据库中 |

## 五、边界情况处理

| 场景 | 处理方式 |
|------|----------|
| 删除根节点（id=0） | 根节点为虚拟节点，不允许删除 |
| 删除有子任务的父任务 | 级联删除所有子任务 |
| 删除无子任务的未挂靠任务 | 直接删除单条记录 |
| 子任务设置权重为 0 | 权重为 0 时视为无效，进度计算时跳过 |
| 无子任务的父任务 | progress 返回 null 或 0 |
| 所有子任务权重为 0 | progress 返回 0 |
| 循环引用 | parent_id 不能形成环，禁止 parent_id = id |
| 更新根节点 | 禁止操作 |
| 修改父任务的 parent_id | 禁止操作 |

## 六、向后兼容性

1. **数据迁移**：新增字段需有默认值或允许 null，确保历史数据兼容
2. **API 兼容**：`/todo/list` 返回结构不变（除新增字段外）
3. **默认值策略**：
   - `parent_id` 默认 0（顶级任务）
   - `priority` 默认 0
   - `weight` 默认 1

## 七、验收标准

### 7.1 功能验收

| 编号 | 验收条件 |
|------|----------|
| AC-01 | 删除父任务时，所有子待办同步被删除 |
| AC-02 | 删除未挂靠任务时，直接删除单条记录 |
| AC-03 | `/todo/tree` 返回以 id=0（待办事项）为根的树形结构 |
| AC-04 | `/todo/list` 接口行为不变，返回扁平列表 |
| AC-05 | 父子任务、未挂靠任务都可以设置优先级 |
| AC-06 | 子任务有权重字段，默认值为 1 |
| AC-07 | 进度计算正确：progress = Σ已完成子任务权重 / Σ子任务总权重 × 100% |
| AC-08 | 进度字段可存储/可实时计算 |
| AC-09 | 语义约束生效：禁止操作根节点，禁止修改 parent_id |
| AC-10 | 树形结构中同时展示父任务和未挂靠任务 |

### 7.2 非功能验收

| 验收条件 |
|---------|
| 删除操作保证原子性 |
| 数据库新增字段对历史数据无影响 |
| 新接口不影响现有接口性能 |
| 错误码区分不同任务类型和错误场景 |

## 八、术语表

| 术语 | 说明 |
|------|------|
| **父任务** | `parent_id = 0`，有子任务，是子待办的上级节点 |
| **未挂靠任务** | `parent_id = 0`，无子任务，不属于任何父任务，直接挂在虚拟根节点下 |
