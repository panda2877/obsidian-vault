# 跨端通用Agent连接工具 — 需求文档

> 版本：v0.2（待技术审阅）

## 1. 项目背景

### 1.1 动机

市面上的对接渠道（微信、QQ、飞书等）存在以下问题：

- **平台限制多**：消息格式受限、机器人 API 各种坑、自定义功能要看平台脸色
- **体验不可控**：消息丢失、延迟、审核风险
- **功能拓展难**：无法深度整合 Agent 的独特能力（记忆浏览、看板管理、多 Profile 切换等）

因此需要一个 **完全由自己掌控的入口**，作为 Hermes Agent 的私有渠道。

### 1.2 现状

用户已深度魔改 Hermes Agent，包括：

| 改动 | 说明 |
|------|------|
| SOUL 加载（LanceDB 模式） | `agent/prompt_builder.py` |
| 记忆加载（LanceDB 模式） | `tools/memory_tool.py` |
| agent_registry 表 | `kanban_db.py` |
| LiteLLM Proxy 网关 | 配置层 |
| Obsidian 接入 | 配置层 |
| 看板系统全量修改 | 与原生侧重点不同 |

### 1.3 核心诉求

> 「我想要一个自己的渠道，Web / PC / 移动端都能用，随时跟 Agent 会话。」

---

## 2. 项目目标

### 2.1 总体目标

构建一套 **跨端通用 Agent 连接工具**，作为 Hermes Agent 的官方跨端客户端，同时开源供他人使用。

### 2.2 核心原则

| 原则 | 说明 |
|------|------|
| **不改后端** | 利用 Hermes 内置 api_server，零后端代码修改 |
| **逐步剥离** | 先把 MVP 跑起来，再逐步把魔改功能剥离到 UI 层 |
| **渐进增强** | 先做 Web 端验证概念，再铺到 PC 和移动端 |
| **开源友好** | 全栈开源，别人 fork 即用，也可只取前端接自己的后端 |

### 2.3 非目标

- ❌ 不做通用的 Agent 连接框架
- ❌ 不做适配层/抽象接口（别人接入只需实现 REST API）
- ❌ 不做后端插件化（未来再考虑）

## 4. 核心场景

### 场景一：日常 Agent 对话 🗣️

```
用户打开前端 → 选择 Profile → 输入消息
    ↓
前端调 Hermes api_server → Agent 处理 → 流式返回
    ↓
前端实时渲染回复 → 支持文件/图片/富卡片
```

### 场景二：多端无缝切换 📱💻

```
PC 上聊到一半 → 合上电脑 → 手机打开 PWA → 继续聊
    ↓
会话上下文由 Hermes 网关保持，前端只负责展示
```

### 场景三：Agent 功能面板整合 🧩

```
聊天界面之外，逐步整合：
├── 记忆浏览器（查看/搜索对话历史）
├── 看板管理面板（任务状态、调度）
├── Profile 管理（切换人格设定）
├── Agent 注册表（查看各 Agent 状态）
└── 更多自定义面板
```

## 6. UI 设计规范（v0.2）

### 6.1 页面结构

全屏三段式布局：

```
┌────────────────────────────────────────────────────┐
│  Topbar（公用）  Hermes Connect  | 状态 | 连接信息 │
├──────────┬──────────────────┬─────────────────────┤
│ 功能区   │ Agent 栏（共用）  │  消息栏 / 辅助面板   │
│ Chat    │                  │                     │
│ Setting │                  │  辅助面板默认收起     │
│          │                  │  宽度30%（可选展开）  │
└──────────┴──────────────────┴─────────────────────┘
```

### 6.2 配色方案

深色主题 + 琥珀金强调色：

| 用途 | 色值 | 说明 |
|------|------|------|
| 主背景 | `#0F0F10` | 深色基调 |
| 卡片背景 | `#18181B` | 面板、卡片 |
| 次级背景 | `#27272A` | 输入框、hover |
| 强调色（琥珀金） | `#D4A853` | 发送按钮、选中态、活跃项 |
| 在线绿 | `#22C55E` | 连接状态 |
| 主文字 | `#FAFAFA` | 标题、内容 |
| 次级文字 | `#A1A1AA` | 辅助说明 |
| 占位符 | `#71717A` | 输入框占位 |
| 边框 | `#3F3F46` | 分割线 |

### 6.3 组件规范

- **圆角**：统一 8px（`--radius-card: 8px`）
- **图标**：Feather Icons，stroke-width: 1.5，inline SVG
- **阴影**：`rgba(0, 0, 0, 0.3)`
- **间距基准**：4px 倍数

### 6.4 桌面端布局

- 功能区（左侧）：固定宽度 200px
- Agent 栏（中间）：固定宽度 280px
- 消息栏（右侧）：flex: 1，减去辅助面板 30%
- 辅助面板：30% 宽度，默认收起，点击展开

### 6.5 移动端适配（< 768px）

**多级页面结构：**
- 页面一：Agent 栏（列表视图）
- 页面二：消息栏（聊天视图）
- 页面三：辅助面板（浮窗模式）

**底部导航切换三个页面**

**返回按钮**：消息栏顶部左侧，显示 `<` 图标，点击返回 Agent 列表

### 6.6 消息栏功能

| 图标 | 功能 | 说明 |

```

│  │  └── 移动（H5 + PWA）                      │   │
│  └─────────────────┬─────────────────────────┘   │
│                    │ HTTP / SSE                   │
└────────────────────┼─────────────────────────────┘
                     │

│  │                                            │ │
│  │  ├── api_server（端口 8642）                │ │

│  │  │   · 看板系统                            │ │
│  │  │                                         │ │
│  │  └── Memory 服务（端口 9091）               │ │
```

### 6.2 前端技术栈

| 技术 | 选型 | 理由 |
|------|------|------|
| 框架 | **uni-app** | 一套代码三端编译，Vue 生态 |
| PC 端 | **Tauri** | 极轻量（~5MB），原生体验 |
| 移动端 | **PWA** | 零安装，离线可用，推送通知 |
| HTTP 客户端 | **uni.request / fetch** | 标准 HTTP，直调 Hermes API |
| 流式 | **EventSource / fetch + ReadableStream** | SSE 流式接收 |

### 6.3 后端技术栈

| 技术 | 选型 | 说明 |
|------|------|------|
| Agent 引擎 | **Hermes（你的魔改版）** | 不改一行代码 |
| API 层 | **Hermes 内置 api_server** | 端口 8642，OpenAI 兼容 |
| 记忆存储 | **LanceDB（你的魔改）** | 独立 FastAPI 服务，端口 9091 |
| 未来 BFF | **Python FastAPI** | 可直接 import Hermes 内部模块 |

### 6.4 数据流

```
用户输入 → 前端 → POST /v1/chat/completions → Hermes api_server
    ↓                                                    ↓
前端渲染 ← SSE stream ← Agent 流式回复 ← AIAgent 处理消息
```

### 6.5 资源消耗

| 组件 | 内存 | 说明 |
|------|------|------|
| Hermes 网关（含 agent） | ~327 MB | 已在运行 |
| api_server 启用 | ~0 MB | 网关内建 |
| Memory 服务（LanceDB） | ~41 MB | 独立进程，按需启用 |
| 前端静态文件服务 | ~0 MB | nginx 一发 |
| 未来 BFF | ~30-50 MB | 后续迭代 |
| **UI 层新增总计** | **~0-91 MB** | |

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Hermes api_server 性能不足 | 高并发时响应慢 | MVP 阶段单人使用，无此问题 |
| PWA 在 iOS 上推送受限 | 移动端通知不及时 | 后续可编译 uni-app 到原生 App |
| 魔改功能剥离到 UI 层复杂度高 | 开发周期延长 | 逐步迭代，不一次性重构 |
| 开源后别人接入门槛高 | 社区采纳率低 | 提供完整 API 文档 + 示例 |
