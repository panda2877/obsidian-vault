## 1. 技术评审摘要

### 1.1 方案可行性评估

| 维度 | 评估 | 说明 |
|------|------|------|
| **架构可行性** | ✅ 通过 | uni-app + Hermes api_server 组合可行，零后端改造满足需求 |
| **技术风险** | ⚠️ 中低 | SSE 流式渲染、多端适配需重点关注 |
| **开发成本** | ✅ 合理 | MVP 约 6.5 天，后续分阶段迭代 |
| **维护成本** | ✅ 低 | 一套代码三端，后期维护压力小 |

### 1.2 核心结论

1. **无需自建数据库**：所有数据由 Hermes api_server 管理，前端仅需做缓存（Session 列表、会话历史）
2. **接口对接明确**：Hermes api_server 已暴露 OpenAI 兼容格式，前端直接调用
3. **推荐技术选型**：uni-app + uView UI + Pinia 状态管理

## 2. 数据库表结构设计

### 2.1 设计原则

> **结论：前端无需独立数据库，所有数据由 Hermes 管理**

**理由**：
- Hermes api_server 已实现会话（Session）管理、消息存储
- LanceDB 记忆由独立服务（端口 9091）管理
- 前端仅需做本地缓存（如未读消息、用户偏好设置）

### 2.2 本地轻量存储（可选）

若需要本地缓存，可使用 uni-app 的 `storage` 或 `pinia-plugin-persistedstate`：

```typescript
// 场景：缓存 Session 列表（避免每次从 api_server 拉取）
interface LocalCache {
  session_list: SessionMeta[];  // 仅缓存元数据，非消息内容
  user_preferences: {
    theme: 'dark' | 'light';
    last_agent_id: string;
    panel_collapsed: boolean;
  };
  draft_message: string;  // 草稿消息（防止刷新丢失）
}
```

### 2.3 第三方依赖

| 存储类型 | 技术选型 | 用途 |
|----------|----------|------|
| **后端数据** | Hermes api_server | Session、消息、Agent 列表 |
| **记忆数据** | LanceDB（端口 9091） | User/Soul/Memory 数据 |
| **前端缓存** | localStorage / pinia | 用户偏好、Session 缓存 |

### 4.3 关键实现点

#### 4.3.1 流式消息渲染

```typescript
// services/api.ts
export async function sendMessage(
  agentId: string,
  sessionId: string,
  messages: Message[],
  onChunk: (content: string) => void
): Promise<void> {
  const response = await fetch(`${HERMES_API}/v1/chat/completions`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      agent_id: agentId,
      session_id: sessionId,
      messages: messages.map(m => ({ role: m.role, content: m.content })),
      stream: true
    })
  });

  const reader = response.body?.getReader();
  const decoder = new TextDecoder();

  while (reader) {
    const { done, value } = await reader.read();
    if (done) break;

    const chunk = decoder.decode(value);
    // 解析 SSE 格式
    const lines = chunk.split('\n');
    for (const line of lines) {
      if (line.startsWith('data: ')) {
        const data = JSON.parse(line.slice(6));
        if (data.choices?.[0]?.delta?.content) {
          onChunk(data.choices[0].delta.content);
        }
      }
    }
  }
}
```

## 6. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| Hermes api_server 接口不稳定 | 中 | 封装 API 层，接口变化时只需修改一处 |
| SSE 在部分浏览器兼容性问题 | 中 | 使用 fetch + ReadableStream，polyfill EventSource |
| 大量消息导致虚拟滚动卡顿 | 中 | 分页加载 + 下拉刷新，不一次性渲染全部 |
| 移动端 PWA iOS 支持不完整 | 低 | 预留编译为原生 App 的能力 |
| 主题定制覆盖不全 | 低 | 建立 Design Token 文档，统一管理颜色变量 |
