## 2. 前端技术选型

### 2.1 框架选型

| 方案 | 评分 | 理由 |
|------|------|------|
| **uni-app** | ⭐⭐⭐⭐⭐ | **选定** — 一套代码三端编译，Vue 生态，你熟悉 |
| Flutter | ⭐⭐⭐⭐ | 全端覆盖好，但 Dart 学习成本，且与现有技术栈不匹配 |
| React Native | ⭐⭐⭐ | PC 端支持弱，Web 端需要额外适配 |
| 纯 PWA | ⭐⭐⭐ | 只有 Web 端，PC 端无原生体验 |

### 2.2 三端方案

| 端 | 方案 | 大小 | 内存 | 理由 |
|----|------|------|------|------|
| **Web** | uni-app 编译 H5 | ~5 MB | 浏览器自管 | 开发调试最快 |
| **PC** | uni-app H5 + **Tauri** 打包 | ~5 MB（壳） | ~30-50 MB | 极轻量，原生窗口、系统托盘、快捷键 |
| **移动** | uni-app H5 + **PWA** | ~5 MB | 浏览器自管 | 零安装，离线可用，iOS 16.4+ 支持推送 |

### 2.3 为什么选 Tauri 而不是 Electron

| 对比项 | Tauri | Electron |
|--------|-------|----------|
| 应用体积 | ~5 MB | ~120-150 MB |
| 内存占用 | ~30-50 MB | ~100-300 MB |
| 系统 API | Rust 原生绑定 | Node.js 绑定 |
| 学习成本 | 需要了解 Rust（但壳代码极少） | 纯 JS/TS |

Tauri 壳代码极少——你只需要写几行 Rust 配置窗口标题、托盘、快捷键，核心 UI 还是 uni-app 的 Vue 代码。

### 2.4 为什么移动端先走 PWA 而不是 uni-app App 编译

| 对比项 | PWA | uni-app App 编译 |
|--------|-----|-----------------|
| 开发成本 | 加两个配置文件 | 需额外配置原生插件 |
| 安装门槛 | 浏览器打开 → 添加到桌面 | 需应用商店或 APK 分发 |
| 体积 | ~5 MB 缓存 | ~30-50 MB 安装包 |
| 性能 | 浏览器 WebView | 也是 WebView 套壳，无本质区别 |
| 推送 | iOS 16.4+ 支持 | 需原生推送插件 |

**先 PWA 顶着，觉得不够再编译 uni-app 到 App。** 代码不用改，一键编译。

## 3. 后端技术选型

### 3.1 核心策略：零后端修改

```
Hermes 已内置 api_server（gateway/platforms/api_server.py）
    ↓
只需在 config.yaml 启用一行配置
    ↓
无需任何后端代码开发
```

### 3.2 api_server 能力清单

| 端点 | 说明 | 用途 |
|------|------|------|
| `POST /v1/chat/completions` | OpenAI 兼容聊天补全 | 发送消息、获取回复 |
| `POST /v1/runs` | 启动运行（返回 run_id） | 异步任务 |
| `GET /v1/runs/{id}/events` | SSE 流式事件 | 实时流式回复 |
| `GET /v1/models` | 列出可用模型 | 前端选择模型 |
| `GET /health` | 健康检查 | 后端状态监测 |

**完整端点见源码：** `gateway/platforms/api_server.py`（~3400 行，成熟稳定）

### 3.3 启用方式

```yaml
# config.yaml
gateway:
  platforms:
    api_server:
      enabled: true
      port: 8642
      host: 0.0.0.0  # 允许局域网/本机访问
```

```bash
# 启动
hermes gateway start
# → localhost:8642 就开了
```

### 3.4 数据流

```
用户输入 → 前端
    ↓ fetch / axios
POST /v1/chat/completions
    ↓
Hermes api_server → 创建 AIAgent
    ↓ 调你的魔改 Hermes 核心
AIAgent 处理（SOUL + 记忆 + 工具）
    ↓ SSE stream
前端逐块渲染回复
```

### 3.5 未来 BFF 层

当需要暴露记忆/看板等扩展接口时，加一层 Python FastAPI：

```python
# BFF — 直接 import Hermes 内部模块
from tools.memory_tool import read_memory, write_memory
from hermes_cli.kanban_db import list_tasks

@app.get("/api/memory/{profile}")
async def get_memory(profile: str):
    context = read_memory(profile)  # 直接调你的魔改
    return {"context": context}
```

## 4. 跨端方案对比

### 4.1 方案对比总表

| 方案 | Web | PC | 移动 | 一套代码？ | 性能 | 包体积 | 推荐度 |
|------|-----|-----|------|-----------|------|--------|--------|
| **uni-app H5 + Tauri + PWA** | ✅ | ✅ | ✅ | ✅ 95% | ⭐⭐⭐⭐ | 轻 | ⭐⭐⭐⭐⭐ |
| uni-app + uni-app App | ✅ | ⚠️ 弱 | ✅ | ✅ 90% | ⭐⭐⭐ | 中 | ⭐⭐⭐ |
| Electron + React | ✅ | ✅ | ❌ | ⚠️ 需适配 | ⭐⭐⭐ | 重 | ⭐⭐ |
| Flutter | ✅ | ✅ | ✅ | ✅ 90% | ⭐⭐⭐⭐ | 中 | ⭐⭐⭐ |

### 4.2 推荐方案详解

```
开发时：uni-app（Vue 3 + Vite）
    ↓ 编译
Web 端  →  dist/build/h5/         → 浏览器 / Nginx
PC 端   →  dist/build/h5/ + Tauri  → 桌面应用（~5 MB）
移动端  →  dist/build/h5/ + PWA    → 添加到桌面
```

**开发工作流：**
```bash
# 日常开发
npm run dev:h5        # 浏览器热更新调试

# 构建
npm run build:h5      # 构建 Web
tauri build           # 构建 PC 桌面端（自动引用 H5 构建产物）

# PWA 不需要构建，H5 产物加两个配置文件即可
```

## 5. 通信协议

### 5.1 主要协议：HTTP + SSE

| 协议 | 用途 | 说明 |
|------|------|------|
| HTTP REST | 发送消息、查询状态 | POST/GET 标准请求 |
| SSE (Server-Sent Events) | 流式接收 Agent 回复 | 单向实时推送，比 WebSocket 轻 |
| WebSocket | ❌ 不需要 | SSE 已满足聊天场景 |

### 5.2 前端调用示例

```javascript
// 发送消息（非流式）
const res = await fetch('http://localhost:8642/v1/chat/completions', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    model: 'hermes-agent',
    messages: [{ role: 'user', content: '你好' }]
  })
})
const data = await res.json()
console.log(data.choices[0].message.content)

// 流式接收（SSE）
const res = await fetch('http://localhost:8642/v1/chat/completions', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    model: 'hermes-agent',
    messages: [{ role: 'user', content: '你好' }],
    stream: true
  })
})
const reader = res.body.getReader()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  // 逐块渲染
}
```

### 5.3 会话保持

```
Hermes 网关内置会话管理
    ↓
通过 X-Hermes-Session-Id header 维持上下文
    ↓
前端不需要做任何会话管理
```

## 6. 资源消耗

### 6.1 服务器端

| 组件 | 内存 | CPU | 磁盘 | 说明 |
|------|------|-----|------|------|
| Hermes 网关（含 agent） | ~327 MB | 推理时高 | ~2 GB | 已在运行 |
| api_server 启用 | ~0 MB | ~0% | 0 | 网关内建 |
| Memory 服务（LanceDB） | ~41 MB | ~1% | ~100 MB | 独立进程 |
| 前端静态文件 | ~0 MB | ~0% | ~5 MB | Nginx 一发 |
| 未来 BFF | ~30-50 MB | 低 | 0 | 后续迭代 |
| **总计** | **~368-418 MB** | | | |

### 6.2 用户终端

| 端 | 内存 | 磁盘 |
|----|------|------|
| 浏览器（Web/PWA） | 浏览器自管（~200-500 MB） | ~5-30 MB 缓存 |
| Tauri 桌面端 | ~30-50 MB | ~5-10 MB |

### 6.3 真正的开销

> **LLM API 调用费。** 前端那点内存跟 Agent 推理时的 Token 消耗比，九牛一毛。

## 7. 技术风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| Hermes api_server 缺少所需端点 | 低 | 中 | BFF 层补，直接 import 内部模块 |
| iOS PWA 推送限制 | 中 | 低 | MVP 先不做推送，后续编译 uni-app App |
| Tauri 打包复杂 | 低 | 低 | Tauri 壳代码极少（~50 行 Rust），官方文档完善 |
| 前端性能瓶颈 | 低 | 低 | 聊天场景不重，虚拟列表可解决 |
