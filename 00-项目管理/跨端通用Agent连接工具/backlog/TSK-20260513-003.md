## 踩坑记录

### 2026-05-14 — 原型修改经验

#### 🕳️ 坑1：`</script>` 在 JS 字符串中导致 HTML 解析提前结束

**现象**：`selectCodeItem` 函数中 Vue 模板代码包含 `</script>` 文本，HTML 解析器将其误认为 `<script>` 结束标签，导致后续所有 JS 源码泄漏到页面中渲染为可见文本。

**修复**：将模板字面量（反引号）改为字符串拼接，用 `'&lt;\\/script&gt;'` 或 `'</scr' + 'ipt>'` 避免 `</script>` 出现在 JS 字符串中。

**教训**：在 `<script>` 标签内的任何字符串中，都不能出现 `</script>` 这个精确文本序列，即使它在注释、模板字面量或字符串变量中。

#### 🕳️ 坑2：模板字面量嵌套导致代码可读性下降

**现象**：`selectFileItem` 和 `selectCodeItem` 使用反引号模板字面量 + `${}` 插值，内部又包含 HTML 标签，多层嵌套后难以维护。

**修复**：改用普通字符串拼接 `'...' + var + '...'`，配合 `escapeHtml()` 确保安全渲染。

**教训**：在 JS 中构建 HTML 内容时，优先用字符串拼接而非模板字面量，避免 `${}` 与 HTML 标签冲突。

#### 🕳️ 坑3：patch 操作依赖唯一匹配字符串

**现象**：多次 patch 同一个大文件时，如果匹配字符串不够独特（如 `TSK-20260513-003` 在项目总览中出现两次），patch 会报 "Found 2 matches" 错误。

**修复**：提供更多上下文行作为匹配字符串，确保唯一性。

**教训**：patch 时始终包含足够多的上下文行（前后各 2-3 行），避免模糊匹配。

#### ✅ 原型修改流程总结

```
老大提需求 → 分析现有结构 → 分步 patch（CSS → HTML → JS）
  → 浏览器验证 → 检查控制台 → 发现问题 → patch 修复 → 再次验证
```

关键原则：
- 每次只改一个逻辑区域（CSS / HTML / JS 分开）
- 改完立即浏览器验证
- 用 `browser_vision` 看视觉效果，`browser_console` 查 JS 错误
- 遇到 JS 源码泄漏 → 先检查 `</script>` 是否出现在字符串中
