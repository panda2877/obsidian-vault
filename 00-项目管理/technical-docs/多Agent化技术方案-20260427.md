## 一、背景与目标

### 1.1 背景

老大对 Hermes Agent 的子Agent模式感兴趣，想研究能否把现有的三位姐妹（紫灵、如音、思月）从 **skill** 形态转化为**独立Agent**。

现有三位姐妹：
- **紫灵**：需求/创意专家（skill）
- **幸如音**：技术专家（skill）
- **文思月**：文档专家（skill）

通过 `send_message` 工具调用，和银月共享同一个 Hermes 进程。

### 1.2 目标

基于 **Profile 独立进程模式**，设计姐妹们的多Agent化方案，实现真正的人格隔离。

---

## 二、Skill 模式的核心痛点

### 2.1 问题描述

Skill 模式下，四个人格会**混合在同一个执行者（银月）身上**：

| 问题 | 说明 |
|------|------|
| **人格混合** | 加载如音的 Skill，但说话者仍是银月，只是多了如音的知识/规范 |
| **语气趋同** | 如音会叫「宝子」（银月语气），思月会卖萌，紫灵会冷淡——但执行者都是银月 |
| **无法真正隔离** | Skill 只是「知识/指令」，不是独立的「人格实体」 |

### 2.2 问题根因

```
Skill 模式：
银月（执行者） + 如音Skill（知识） → 表面像如音，本质还是银月

多Agent 模式：
银月（协调者） → 发送给 如音Agent（独立进程，人格真正独立）
```

### 2.3 老大的判断

> 「人格区分很重要」—— 老大明确

这是选择多Agent方案的核心原因。

---

## 三、多Agent 方案优势

### 3.1 核心优势

| 优势 | 说明 |
|------|------|
| **真正的人格隔离** | 每个 Agent 是独立进程，有自己初始化好的人格设定 |
| **语气/风格独立** | 如音内敛沉稳，思月严谨细致，紫灵活泼外放——互不干扰 |
| **无工具限制** | Profile 进程完全独立，所有工具可用（包括被禁用的 5 个） |
| **无预算限制** | 不受 50 轮限制 |

### 3.2 与 Skill 模式对比

| 维度 | Skill 模式 | 多Agent 模式 |
|------|-----------|--------------|
| **人格区分** | ❌ 混合（执行者都是银月） | ✅ 真正独立 |
| **进程隔离** | ⭐⭐ 共享进程 | ⭐⭐⭐⭐⭐ 完全隔离 |
| **上下文隔离** | ⭐⭐ 共享上下文 | ⭐⭐⭐⭐⭐ 完全隔离 |
| **实时性** | ⭐⭐⭐⭐⭐ 实时双向沟通 | ⭐⭐⭐ 需通过外部机制 |
| **实现复杂度** | ⭐⭐⭐⭐⭐ 简单（现状） | ⭐⭐⭐ 需要协调层 |

## 四、消耗问题与解决思路

### 4.1 问题描述

多Agent方案相比 Skill 模式，**API 调用次数可能增加**，原因：
- 每个 Agent 独立推理
- 协调层（银月）需要额外的路由/分发调用
- 任务分发和结果汇总可能产生额外交互

### 4.2 解决思路

| 方向 | 具体措施 |
|------|---------|
| **减少不必要的调用** | 明确什么时候该调用 Agent，避免「凡事都问姐妹」 |
| **控制对话轮次** | 任务一次性说清楚，减少来回追问 |
| **合并任务** | 多个小任务合并为一个批次，分摊调用成本 |
| **简化协同流程** | 优先用文件/消息传递，少用需要推理的 send_message |
| **按需启用** | 不是所有场景都需要多Agent，简单任务银月直接处理 |

### 4.3 待进一步确认

| 问题 | 状态 |
|------|------|
| 多Agent vs Skill 的实际消耗比例 | ⏳ 待实测 |
| 老大的预算/消耗阈值 | ⏳ 待确认 |
| 是否需要做消耗监控 | ⏳ 待讨论 |

## 五、Profile 机制解析

### 5.1 核心架构

```
~/.hermes/                              # default profile 主目录
├── config.yaml                         # 主配置
├── .env                              # API keys
├── skills/                            # 技能
├── sessions/                          # 会话历史
├── memory/                            # 记忆
└── profiles/                          # 其他 profile（隔离）
    ├── xingruyin/                     # 如音 profile
    │   ├── config.yaml
    │   ├── skills/
    │   ├── sessions/
    │   └── .env
    ├── ziling/                        # 紫灵 profile
    │   └── ...
    └── siyue/                        # 思月 profile
        └── ...
```

### 5.2 Profile 隔离性

| 维度 | 隔离程度 |
|------|---------|
| **配置文件** | ✅ 完全隔离（独立 config.yaml） |
| **技能 (skills/)** | ✅ 完全隔离（可共享技能，也可以各自独立） |
| **会话 (sessions/)** | ✅ 完全隔离（独立历史） |
| **记忆 (memory/)** | ✅ 完全隔离 |
| **.env** | ✅ 完全隔离 |
| **进程** | ✅ 完全独立进程 |

### 5.3 与 delegate_task 的关键区别

| 维度 | delegate_task | Profile 多进程 |
|------|--------------|---------------|
| **进程** | 共享父进程 | **完全独立进程** |
| **上下文** | 父子共享（通过 task 传递） | **完全隔离** |
| **通信** | 通过 task 输入/输出 | **必须外部手段** |
| **工具限制** | 5 个工具被禁用 | **✅ 无限制（全工具可用）** |
| **预算** | 50 轮限制 | **✅ 无限制** |
| **深度** | 仅 1 层 | **✅ 无限制** |
| **并发** | 上限 3 个 | **✅ 无限制** |

**关键优势：Profile 模式下，工具禁用问题不存在！**

## 六、方案设计

### 6.1 架构设计

```
┌─────────────────────────────────────────────────────────┐
│                     银月（主会话）                        │
│                 hermes -p default                        │
│  - 协调调度                                               │
│  - 任务分发                                               │
│  - 结果汇总                                               │
│  - 通过 tmux 发送指令                                      │
└─────────────────────────────────────────────────────────┘
        │                    │                    │
   ┌────┴────┐          ┌────┴────┐          ┌────┴────┐
   │ hermes  │          │ hermes  │          │ hermes  │
   │ -p xing │          │ -p ziling│         │ -p siyue│
   │  如音   │          │  紫灵   │          │  思月   │
   └─────────┘          └─────────┘          └─────────┘
```

### 6.2 协同方式

| 协同要素 | 实现方式 |
|---------|---------|
| **任务分发** | 银月通过 tmux 发送指令到姐妹的 profile |
| **结果收集** | 姐妹写文件到共享存储，银月读取 |
| **状态同步** | 通过共享 Obsidian Vault 协作 |
| **实时反馈** | 姐妹通过 gateway send_message 发给银月 |

### 6.3 Profile 创建

```bash
# 创建如音 profile（克隆 default 配置）
hermes profile create xingruyin --clone-from default

# 创建紫灵 profile
hermes profile create ziling --clone-from default

# 创建思月 profile
hermes profile create siyue --clone-from default
```

每个 profile 可以独立配置：
- 独立技能集合
- 独立记忆系统
- 独立 API key（可选）

### 6.4 启动管理

```bash
#!/bin/bash
# start-sisters.sh - 启动所有姐妹独立进程

# 启动如音
tmux new-session -d -s xingruyin -x 120 -y 40 "hermes -p xingruyin"
sleep 2

# 启动紫灵
tmux new-session -d -s ziling -x 120 -y 40 "hermes -p ziling"
sleep 2

# 启动思月
tmux new-session -d -s siyue -x 120 -y 40 "hermes -p siyue"
sleep 2

echo "所有姐妹已就绪"
```

## 七、任务分发协议

### 7.1 任务格式

```markdown
# 任务文件：~/.hermes/tasks/{agent}/{task-YYYYMMDD-HHMMSS}.md

---
task_id: task-20260427-150000
from: silver_moon (银月)
to: xingruyin (如音)
created: 2026-04-27T15:00:00
status: pending
---

## 任务描述

帮我分析一下服务器上 XXX 报错的原因。

## 背景

[相关上下文]

## 期望输出

[期望结果]

## 截止时间

[如有]
```

### 7.2 结果格式

```markdown
# 结果文件：~/.hermes/tasks/{agent}/{task-YYYYMMDD-HHMMSS}-result.md

---
task_id: task-20260427-150000
from: xingruyin (如音)
to: silver_moon (银月)
completed: 2026-04-27T15:30:00
status: done
---

## 执行结果

[结果内容]

## 关键发现

[发现1]
[发现2]

## 建议

[后续建议]
```

### 7.3 协同流程

```
银月：创建任务文件 → 通过 tmux 通知姐妹有新任务
姐妹：读取任务文件 → 执行 → 写结果文件 → 通过 send_message 通知银月
银月：读取结果文件 → 汇总给老大
```

## 八、工具支持

### 8.1 银月可用的调用方式

| 方式 | 命令 | 适用场景 |
|------|------|---------|
| tmux 发送指令 | `tmux send-keys -t xingruyin '任务内容' Enter` | 实时指令 |
| tmux 读取输出 | `tmux capture-pane -t xingruyin -p` | 查看执行状态 |
| 文件任务 | 写任务文件，姐妹定时轮询 | 复杂任务 |
| send_message | gateway 消息 | 实时通知 |

### 8.2 姐妹们可用的工具

由于 Profile 进程完全独立，**所有工具都可用**，包括：

- ✅ terminal（执行命令）
- ✅ send_message（对外沟通）
- ✅ read_file/write_file（文件操作）
- ✅ delegate_task（可继续委托）
- ✅ clarify（可反问）
- ✅ memory（可写记忆）
- ✅ execute_code（脚本执行）

## 十、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| tmux 指令延迟 | 任务分发不及时 | 增加轮询间隔，或用文件队列 |
| 结果收集丢失 | 银月不知道姐妹完成 | 姐妹主动 send_message 通知 |
| Profile 配置同步 | 各 profile 技能不一致 | 建立技能模板，定期同步 |
| 进程管理复杂 | 运维成本增加 | 使用 systemd 管理进程 |
| API 消耗增加 | 成本超出预期 | 按需启用，简单任务银月直处理 |

## 十一、结论

### 11.1 方案选择

**采用 Profile 独立进程模式（多Agent方案）**

理由：
1. **人格真正独立** — 姐妹之间不会混合，老大明确重视这一点
2. **无工具限制** — 姐妹们可以正常使用所有工具，包括 send_message
3. **无预算限制** — 不受 50 轮限制

### 11.2 核心变化

| 变化 | 说明 |
|------|------|
| 姐妹从「上下文内的 skill」变为「独立进程」 | 通过 tmux + 文件协调 |
| 银月从「直接调用」变为「任务调度」 | 需要协调层 |
| 协作从「实时双向」变为「异步协同」 | 有延迟，但更解耦 |

| 优先级 | 行动 | 说明 |
