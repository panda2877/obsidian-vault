## 一、背景与目标

### 1.1 背景

老大对 Hermes Agent 的子Agent模式感兴趣，想研究能否把现有的三位姐妹（紫灵、如音、思月）从 **skill** 形态转化为**子Agent**。

现有三位姐妹：
- **紫灵**：需求/创意专家（skill）
- **幸如音**：技术专家（skill）
- **文思月**：文档专家（skill）

通过 `send_message` 工具调用，和银月共享同一个 Hermes 进程。

### 1.2 目标

基于 **Profile 独立进程模式**，设计姐妹们的子Agent化方案。

## 二、Profile 机制解析

### 2.1 核心架构

```
~/.hermes/                              # default profile 主目录
├── config.yaml                         # 主配置
├── .env                              # API keys
├── skills/                            # 技能
├── sessions/                          # 会话历史
├── memory/                            # 记忆
└── profiles/                          # 其他 profile（隔离）
    ├── xingruyin/                     # 如音 profile
    │   ├── config.yaml
    │   ├── skills/
    │   ├── sessions/
    │   └── .env
    ├── ziling/                        # 紫灵 profile
    │   └── ...
    └── siyue/                        # 思月 profile
        └── ...
```

### 2.2 Profile 隔离性

| 维度 | 隔离程度 |
|------|---------|
| **配置文件** | ✅ 完全隔离（独立 config.yaml） |
| **技能 (skills/)** | ✅ 完全隔离（可共享技能，也可以各自独立） |
| **会话 (sessions/)** | ✅ 完全隔离（独立历史） |
| **记忆 (memory/)** | ✅ 完全隔离 |
| **.env** | ✅ 完全隔离 |
| **进程** | ✅ 完全独立进程 |

### 2.3 与 delegate_task 的关键区别

| 维度 | delegate_task | Profile 多进程 |
|------|--------------|---------------|
| **进程** | 共享父进程 | **完全独立进程** |
| **上下文** | 父子共享（通过 task 传递） | **完全隔离** |
| **通信** | 通过 task 输入/输出 | **必须外部手段** |
| **工具限制** | 5 个工具被禁用 | **✅ 无限制（全工具可用）** |
| **预算** | 50 轮限制 | **✅ 无限制** |
| **深度** | 仅 1 层 | **✅ 无限制** |
| **并发** | 上限 3 个 | **✅ 无限制** |

**关键优势：Profile 模式下，工具禁用问题不存在！**

## 三、方案设计

### 3.1 架构设计

```
┌─────────────────────────────────────────────────────────┐
│                     银月（主会话）                        │
│                 hermes -p default                        │
│  - 协调调度                                               │
│  - 任务分发                                               │
│  - 结果汇总                                               │
│  - 通过 tmux 发送指令                                      │
└─────────────────────────────────────────────────────────┘
        │                    │                    │
   ┌────┴────┐          ┌────┴────┐          ┌────┴────┐
   │ hermes  │          │ hermes  │          │ hermes  │
   │ -p xing │          │ -p ziling│         │ -p siyue│
   │  如音   │          │  紫灵   │          │  思月   │
   └─────────┘          └─────────┘          └─────────┘
```

### 3.2 协同方式

| 协同要素 | 实现方式 |
|---------|---------|
| **任务分发** | 银月通过 tmux 发送指令到姐妹的 profile |
| **结果收集** | 姐妹写文件到共享存储，银月读取 |
| **状态同步** | 通过共享 Obsidian Vault 协作 |
| **实时反馈** | 姐妹通过 gateway send_message 发给银月 |

### 3.3 Profile 创建

```bash
# 创建如音 profile（克隆 default 配置）
hermes profile create xingruyin --clone-from default

# 创建紫灵 profile
hermes profile create ziling --clone-from default

# 创建思月 profile
hermes profile create siyue --clone-from default
```

每个 profile 可以独立配置：
- 独立技能集合
- 独立记忆系统
- 独立 API key（可选）

### 3.4 启动管理

```bash
#!/bin/bash
# start-sisters.sh - 启动所有姐妹独立进程

# 启动如音
tmux new-session -d -s xingruyin -x 120 -y 40 "hermes -p xingruyin"
sleep 2

# 启动紫灵
tmux new-session -d -s ziling -x 120 -y 40 "hermes -p ziling"
sleep 2

# 启动思月
tmux new-session -d -s siyue -x 120 -y 40 "hermes -p siyue"
sleep 2

echo "所有姐妹已就绪"
```

## 四、任务分发协议

### 4.1 任务格式

```markdown
# 任务文件：~/.hermes/tasks/{agent}/{task-YYYYMMDD-HHMMSS}.md

---
task_id: task-20260427-150000
from: silver_moon (银月)
to: xingruyin (如音)
created: 2026-04-27T15:00:00
status: pending
---

## 任务描述

帮我分析一下服务器上 XXX 报错的原因。

## 背景

[相关上下文]

## 期望输出

[期望结果]

## 截止时间

[如有]
```

### 4.2 结果格式

```markdown
# 结果文件：~/.hermes/tasks/{agent}/{task-YYYYMMDD-HHMMSS}-result.md

---
task_id: task-20260427-150000
from: xingruyin (如音)
to: silver_moon (银月)
completed: 2026-04-27T15:30:00
status: done
---

## 执行结果

[结果内容]

## 关键发现

[发现1]
[发现2]

## 建议

[后续建议]
```

### 4.3 协同流程

```
银月：创建任务文件 → 通过 tmux 通知姐妹有新任务
姐妹：读取任务文件 → 执行 → 写结果文件 → 通过 send_message 通知银月
银月：读取结果文件 → 汇总给老大
```

## 五、工具支持

### 5.1 银月可用的调用方式

| 方式 | 命令 | 适用场景 |
|------|------|---------|
| tmux 发送指令 | `tmux send-keys -t xingruyin '任务内容' Enter` | 实时指令 |
| tmux 读取输出 | `tmux capture-pane -t xingruyin -p` | 查看执行状态 |
| 文件任务 | 写任务文件，姐妹定时轮询 | 复杂任务 |
| send_message | gateway 消息 | 实时通知 |

### 5.2 姐妹们可用的工具

由于 Profile 进程完全独立，**所有工具都可用**，包括：

- ✅ terminal（执行命令）
- ✅ send_message（对外沟通）
- ✅ read_file/write_file（文件操作）
- ✅ delegate_task（可继续委托）
- ✅ clarify（可反问）
- ✅ memory（可写记忆）
- ✅ execute_code（脚本执行）

## 六、与 Skill 模式对比

### 6.1 当前 Skill 模式

```
银月（主Agent）
  │
  ├── send_message → 紫灵（skill）→ 回复银月
  ├── send_message → 如音（skill）→ 回复银月
  └── send_message → 思月（skill）→ 回复银月

所有姐妹共享银月的进程、上下文、工具集
```

**特点**：
- 姐妹们在银月上下文内，可以随时补充说明
- 共享工具集，无限制
- 无独立预算限制

### 6.2 Profile 子Agent 模式（方案A）

```
银月（主会话）
  │
  ├── tmux → 如音（独立进程）→ 写文件/send_message → 银月
  ├── tmux → 紫灵（独立进程）→ 写文件/send_message → 银月
  └── tmux → 思月（独立进程）→ 写文件/send_message → 银月
```

**特点**：
- 姐妹完全独立进程，无工具限制
- 通过外部机制协同（tmux + 文件 + send_message）
- 无预算/轮次限制

### 6.3 优缺点对比

| 维度 | Skill 模式 | Profile 子Agent 模式 |
|------|-----------|---------------------|
| **实时性** | ⭐⭐⭐⭐⭐ 实时双向沟通 | ⭐⭐⭐ 需通过外部机制 |
| **工具限制** | ⭐⭐⭐⭐⭐ 无限制 | ⭐⭐⭐⭐⭐ 无限制 |
| **预算限制** | ⭐⭐⭐⭐⭐ 无限制 | ⭐⭐⭐⭐⭐ 无限制 |
| **进程隔离** | ⭐⭐ 共享进程 | ⭐⭐⭐⭐⭐ 完全隔离 |
| **上下文隔离** | ⭐⭐ 共享上下文 | ⭐⭐⭐⭐⭐ 完全隔离 |
| **实现复杂度** | ⭐⭐⭐⭐⭐ 简单（现状） | ⭐⭐⭐ 需要协调层 |
| **协作灵活性** | ⭐⭐⭐⭐ 随时可追问 | ⭐⭐⭐ 需重新发任务 |

## 八、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| tmux 指令延迟 | 任务分发不及时 | 增加轮询间隔，或用文件队列 |
| 结果收集丢失 | 银月不知道姐妹完成 | 姐妹主动 send_message 通知 |
| Profile 配置同步 | 各 profile 技能不一致 | 建立技能模板，定期同步 |
| 进程管理复杂 | 运维成本增加 | 使用 systemd 管理进程 |

## 九、结论

### 9.1 方案选择

**采用 Profile 独立进程模式（方案A）**

理由：
1. **无工具限制** — 姐妹们可以正常使用所有工具，包括 send_message
2. **完全隔离** — 姐妹之间不会互相干扰
3. **无预算限制** — 不受 50 轮限制

### 9.2 核心变化

| 变化 | 说明 |
|------|------|
| 姐妹从「上下文内的 skill」变为「独立进程」 | 通过 tmux + 文件协调 |
| 银月从「直接调用」变为「任务调度」 | 需要协调层 |
| 协作从「实时双向」变为「异步协同」 | 有延迟，但更解耦 |
