## 任务目标

定期检查长时间处于 `running` 状态的任务，检测可能的挂起或崩溃，并通知人类。

## 简化方案（替代原自建 cron 看门狗）

原生 kanban 已有 claim TTL 机制，dispatcher 每 60s 扫描 stale claim 并回收：

```python
# 原生 claim_expires 机制
# 15min TTL 后 claim 自动失效，dispatcher 可重新认领
```

但原生的看门狗只处理 claim 锁，不处理：
1. **无 claim 但 agent 已崩溃**（agent 挂了但没来得及加锁）
2. **超长任务正常执行**（如训练任务跑 10 小时）

## 实现方案

### 基础层（原生已有）
- `kanban_block` + `kanban_heartbeat` — agent 主动保活
- dispatcher claim TTL — 自动回收 stale claim

### 增强层（自建 cron）

```bash
# 每 30 分钟检查一次
*/30 * * * * hermes kanban list --status running
```

检测逻辑：
```python
# 检测满足以下全部条件的任务：
# 1. status = 'running'
# 2. claim_lock IS NULL（无 claim 但在 running）
# 3. started_at < now() - 2h
# → 可能是 agent 挂了没来得及释放锁
```

发现异常后：
1. 任务进入 `blocked`，blocker 写入原因
2. 通知人类：`kanban_comment` 或直接发送消息

## 验收标准

- [ ] cron 检测到疑似挂起任务
- [ ] 任务进入 `blocked` 状态并写入 reason
- [ ] 人类收到通知
