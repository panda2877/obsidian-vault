## 任务目标

重构看板与 Obsidian 的协同模式：**Obsidian 纯读，SQLite 是源（Source of Truth）**。

## 核心变更：单向拉取代替双向同步

**旧方案（废弃）**：双向同步，Obsidian ←→ SQLite，写复杂，容易不一致。

**新方案**：
- **SQLite = 源**，所有任务状态以 SQLite 为准
- **Obsidian = 只读视图**，每次需要时从 SQLite 拉取最新状态
- **不需要人在 Obsidian 修改**看板，修改只在 SQLite 侧进行

## 新建 Skill 1：`kanban-sync`

### 用途

将 SQLite 看板数据（tasks + checkpoints）拉取并写入 Obsidian 对应文件，同时 git commit 推送。

### 触发方式

用户要求"更新 Obsidian 看板"时调用。

### 数据流向

```
原生 kanban.db（tasks 表）
       ↓
  遍历任务
       ↓
Obsidian 文件（backlog/done/TSK-{date}-{seq}.md）
  - 更新 frontmatter（status、priority、updated）
  - 追加 checkpoint 快照到文件末尾
       ↓
  git add → git commit → git push
```

### 文件路径映射

```
task_id = "TSK-20260504-003"
↓ 根据 status 查找目录
backlog/TSK-20260504-003.md  （status: backlog/in_progress/blocked）
done/TSK-20260504-003.md     （status: done/completed）
```

### frontmatter 更新规则

```yaml
status: {最新状态}       # 直接使用 SQLite status
priority: P{p_int}       # INTEGER → P0/P1/P2
assignee: {assignee}
updated: {updated_at}    # 时间戳转 ISO
completed: {completed_at} # 仅 done/completed 时有值
```

### checkpoint 快照追加格式

```markdown
## 快照记录

- **2026-05-04T23:05:05** `wrapping` — agent:end 写入
  - 摘要：TSK-003 Hook 集成 on_task_done 验证通过
```

### 验收标准

- [ ] 从原生 kanban.db 读取 tasks 和 checkpoints
- [ ] 正确更新 Obsidian 文件 frontmatter
- [ ] 追加 checkpoint 快照到文件末尾
- [ ] 自动 git commit + push
- [ ] 脚本可单独运行：`python3 /home/agentuser/.hermes/skills/kanban-sync/scripts/sync.py`

### 已知陷阱

1. 文件可能在 `backlog/` 或 `done/`，根据当前 status 动态查找
2. 部分任务已完成但文件仍在 `backlog/`（历史遗留），需要同时查两个目录

## 新建 Skill 2：`task-preflight`

### 用途

开始任务前，定位 Obsidian 中对应任务的实施方案文档，直接调阅。

### 触发方式

用户说"开始做 TSK-XXX"、"处理任务 XXX"时自动调用。

### 执行逻辑

```
1. 从任务 ID（TSK-YYYY-NNN）解析日期和序号
2. 在 Obsidian 目录中查找对应文件：
   - backlog/TSK-{date}-{seq}.md
   - done/TSK-{date}-{seq}.md
3. 读取文件，提取：
   - frontmatter（title、status、priority、assignee）
   - 任务目标（## 任务目标）
   - 验收标准（## 验收标准）
   - 检查点历史（## 检查点）
4. 如果有 checkpoint，从 SQLite 查最新快照
5. 输出汇总：任务基本信息 + 最新 checkpoint + 建议的下一步
```

### 用途定位

> **不要**重新研读源码出具方案 → 先查 Obsidian 任务卡片，看前人已有什么方案/结论。

### 验收标准

- [ ] 给定 task_id 能正确定位文件
- [ ] 提取任务目标、验收标准、检查点
- [ ] 关联最新 checkpoint（phase/summary）
- [ ] 输出结构化摘要，供 agent 直接参考
