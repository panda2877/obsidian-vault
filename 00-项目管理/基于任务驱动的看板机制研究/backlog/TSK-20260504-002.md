## 任务目标

在 `run_agent.py` 主循环中集成 `on_phase_change` hook，当任务状态发生列间迁移时（inbox→in_progress、in_progress→review、review→done），写入对应 phase 的 checkpoint。

## 触发时机

任务状态从 `inbox/assigned` → `in_progress` → `review` → `done` 的每一次列间迁移

## 状态到 phase 的映射

| 看板列 | checkpoint phase |
|--------|-----------------|
| inbox / assigned | exploring |
| in_progress | implementing |
| review | testing |
| done | wrapping |

## 调用接口

```python
snapshot_provider.write_checkpoint(
    task_id="<任务ID>",
    phase="<implementing|testing|wrapping>",
    summary="<本阶段摘要>",
    findings=["<发现1>", "<发现2>"],
    blockers=["⚠️ <阻塞项>"],
    next_steps=["[ ] <下一步1>", "[ ] <下一步2>"],
    mission_id="<mission_id>",
)
```

## 阻塞说明

**阻塞原因**：`phase_change` 事件在 Hermes Gateway 中不存在，无法通过 Hook 触发。

- `run.py` 中只有 `session:start`、`session:end`、`session:reset`、`agent:start`、`agent:end`、`command:{name}` 事件
- `phase_change` 需要在 `run.py` 中主动 emit，但当前没有这个事件

**前置依赖**：需要先实现 TSK-004（任务状态追踪层），由 task store 负责 track 任务在列间的迁移，然后才能在 phase 变化时触发 hook。

- [ ] 任务状态每次列间迁移都触发 checkpoint 写入
- [ ] `findings`、`blockers`、`next_steps` 字段正确填充
- [ ] 同一个任务的多个 checkpoint 按时间顺序可追溯
