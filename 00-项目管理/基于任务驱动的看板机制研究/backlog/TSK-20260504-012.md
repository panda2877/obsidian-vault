## 任务目标

研究 checkpoint 表各字段与快照机制的映射关系，确定哪些字段由 hook 自动写入、哪些需要从 snapshot 上下文提取，最终形成可落地的写入规范。

## checkpoint 表字段现状

```sql
CREATE TABLE checkpoints (
    id              TEXT PRIMARY KEY,
    task_id         TEXT NOT NULL,
    phase           TEXT NOT NULL,
    summary         TEXT,
    findings        TEXT,       -- JSON 数组
    blockers        TEXT,       -- JSON 数组
    next_steps      TEXT,       -- JSON 数组
    agent_id        TEXT,
    mission_id      TEXT,
    session_id      TEXT,
    created_at      TEXT NOT NULL
);
```

## 快照（Snapshot）机制现状

快照在会话结束时由 `provider.py` 的 `atexit` 触发，写入 JSON 文件，包含：
- `task_goals`：任务目标列表
- `checklist`：子任务清单
- `assignments`：任务分派
- `missing_info`：缺失信息
- `conversation_messages`：完整消息历史

## 待研究问题

1. **phase 映射**：snapshot 无 phase 字段，checkpoint 的 phase 应如何推断？
   - 探索中 → `exploring`
   - 实现中 → `implementing`
   - 收尾 → `wrapping`

2. **summary 映射**：从 `task_goals` 取第一条？还是从会话最后一轮 user message 提取？

3. **findings 映射**：从 snapshot 的 `task_goals` 还是从消息中的决策/发现提取？

4. **blockers 映射**：从 snapshot 的 `missing_info` 直接迁移？

5. **next_steps 映射**：从 snapshot 的 `checklist` 中未完成项迁移？

6. **自动写入 vs 手动补充**：hook 只能写触发时的瞬时上下文，深度信息需要 agent 主动补充
