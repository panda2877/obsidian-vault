## 状态重新评估

**原阻塞原因**：Hermes Gateway 中不存在 `phase_change` 事件，无法通过 Hook 触发。

**新评估结论**：原生 kanban 没有 phase 概念，phase 是 Checkpoint 的自定义维度。阶段推进通过以下时机隐式完成：

| 时机 | 对应 phase |
|------|-----------|
| `agent:start` | `exploring` |
| `kanban_block` 调用 | 阻塞（阶段上下文写入 blockers） |
| `agent:end` | `implementing` 或 `wrapping`（取决于 finished 标志） |

**不再需要独立的 `phase_change` 事件**。

## 变更后的触发机制

```
Hook: agent:start → write_checkpoint(phase='exploring')
Hook: agent:end   → write_checkpoint(phase='implementing'|'wrapping')
Agent 调用 kanban_block → 写入 blockers，阶段保持
```

原生的 `task_events` 表已记录所有任务状态变更（created/assigned/completed/blocked），可通过 `kanban_comment` 或直接查询 DB 获取历史。

## 验收标准（修订）

- [x] 不再依赖 `phase_change` 事件
- [x] 通过 `agent:start` / `agent:end` 隐式覆盖 phase 推进
- [x] `blocked` 状态的 blockers 由 agent 主动通过 `kanban_block` 写入
