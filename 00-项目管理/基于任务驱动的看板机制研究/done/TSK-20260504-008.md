## 任务目标

将自建 `agent_registry` 表迁移到原生 kanban.db，与 Checkpoint 表一同初始化。

## 背景变更

**并发控制已废弃**：原计划用 `agent_registry` 做任务并发控制，但原生 kanban 已有 `claim_lock` + 15min TTL 机制实现分布式锁，无需自建。

`agent_registry` 表的用途改为：**Agent 身份信息注册**（profile/name/role/capabilities/status），用于看板可见性和任务分配参考。

## Schema

```sql
CREATE TABLE IF NOT EXISTS agent_registry (
    id            TEXT PRIMARY KEY,
    profile       TEXT NOT NULL UNIQUE,
    name          TEXT NOT NULL,
    role          TEXT NOT NULL DEFAULT 'generalist',
    capabilities  TEXT NOT NULL DEFAULT '[]',
    status        TEXT NOT NULL DEFAULT 'idle',
    registered_at TEXT NOT NULL
);
```

## 与原生 claim_lock 的区别

| | agent_registry | 原生 claim_lock |
|--|---------------|-----------------|
| 用途 | Agent 身份注册 | 任务并发锁 |
| 生命周期 | Agent 启动时注册 | 任务认领时加锁，完成/超时释放 |
| 持久化 | 长期 | 15min TTL |
