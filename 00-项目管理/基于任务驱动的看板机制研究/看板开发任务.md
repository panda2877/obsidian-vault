## 一、可视化看板方案

### 方案 A：Obsidian + Kanban 插件（推荐轻量级）

**插件选项**：
- [Obsidian Kanban](https://github.com/yoyoy荒/obsidian-kanban) — 支持拖拽、 Markdown 存储、可嵌入标签
- [Kanban](/obsidian-kanban) by mgmeyers — 界面接近 Trello，支持卡片自定义

**优点**：
- 与现有笔记体系无缝整合
- Markdown 文件直接存储，可 git 版本管理
- 无需额外部署服务

**缺点**：
- 多 agent 实时同步需要插件支持（可能有延迟）
- SQLite 状态和 Obsidian 文件需要手动保持同步

**文件格式参考**：
```markdown
---
id: TSK-20260504-001
status: in_progress
priority: P1
assignee: xingruyin
mission_id: mission-alpha
---

## 任务目标

实现支付模块 SQLite 持久化

## 检查点

- [2026-05-04 14:30] phase=implementing | 执行者: xingruyin
  - 摘要: 完成 Schema 设计
  - 阻塞: ⚠️ 缺少沙箱密钥
```

---

### 方案 B：自建 Web 可视化看板（推荐完整功能）

**技术选型建议**：

| 框架 | 特点 | 适合场景 |
|------|------|----------|
| **React + Tailwind + dnd-kit** | 轻量拖拽，组件丰富 | 自建看板核心 |
| **Lattice** | 开源看板，Trello-like | 直接使用或魔改 |
| **Plane** | 开源项目管理，接近 Linear | 长期使用，有 multi-project |
| **GitBoard** | 极简，GitHub Issues 同步 | 已有 GitHub Issues 工作流 |

**数据层**：

```
┌─────────────────────────────────────┐
│  SQLite (checkpoints.db)            │
│  任务状态 + Checkpoint 上下文         │
└───────────────┬─────────────────────┘
                │ 轮询 / WebSocket
                ▼
┌─────────────────────────────────────┐
│  Node.js / Python 后端               │
│  - REST API (读取任务+checkpoint)    │
│  - WebSocket (状态变更推送)          │
│  - 写回 SQLite (状态更新)           │
└───────────────┬─────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│  React 前端                          │
│  - 看板视图 (dnd-kit 拖拽)           │
│  - 任务详情面板 (checkpoint timeline) │
│  - Agent 状态栏                      │
└─────────────────────────────────────┘
```

**优点**：
- 多 agent 实时感知（WebSocket 推送）
- 可自定义 Agent 协作工作流
- 可嵌入 review gate 审批流

**缺点**：
- 需要独立部署服务
- 与 Obsidian 笔记的同步需要额外开发

---

### 方案 C：混合方案（推荐）

- **任务状态**：SQLite + Web 看板（方案 B）
- **任务详情**：Obsidian MD 文件（checkpoint timeline 可读性好）
- **同步机制**：Web 看板状态变更时，写入对应 Obsidian 文件的 frontmatter

## 二、待集成点（优先级排序）

  - 集成点：`run_agent.py` 主循环
  - 触发时机：任务状态从 `inbox/assigned` → `in_progress` → `review` 时
  - 动作：`snapshot_provider.write_checkpoint(task_id, phase=<当前阶段>, blockers=[...], next_steps=[...])`

  - 集成点：`run_agent.py` 主循环
  - 触发时机：任务移至 `done` 时
  - 动作：`snapshot_provider.write_checkpoint(task_id, phase='done', summary='...')`
