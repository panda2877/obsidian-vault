## 接口需求清单

### 🔐 模块一：密钥登录

> 密钥写死在环境变量中，登录成功后 token 长时间驻留，不需要登出功能。

#### 接口 1.1 — 登录验证

| 项目 | 说明 |
|------|------|
| **用途** | 用户输入密钥进行登录验证 |
| **请求字段** | `key` — 用户输入的密钥字符串 |
| **返回字段** | `token` — 登录成功后返回的 token（长时间有效）<br>`expires_in` — token 过期时间（可选） |
| **错误处理** | 密钥错误时返回 401，提示「密钥错误」 |
| **备注** | 密钥对比逻辑在服务端完成，前端只传 key 即可 |

#### 接口 1.2 — Token 验证（中间件/守卫）

| 项目 | 说明 |
|------|------|
| **用途** | 其他接口统一校验 token 是否有效 |
| **请求字段** | `token` — 从请求头携带 |
| **返回字段** | 有效：继续执行请求<br>无效：返回 401，前端跳转登录页 |
| **备注** | 这个不需要单独暴露接口，作为全局中间件实现 |

### 📊 模块二：Token 用量统计

> 数据源为 LiteLLM 接口（后续任务提供），本阶段只梳理需求字段，接口规范留待后续。

#### 接口 2.1 — Token 用量查询

| 项目 | 说明 |
|------|------|
| **用途** | 获取 Token 消耗统计数据，用于图表展示 |
| **请求字段** | `start_time` — 起始时间（必填）<br>`end_time` — 结束时间（必填）<br>`model` — 按模型筛选（可选，不传则查所有模型） |
| **返回字段** | `total_tokens` — 总消耗 token 数<br>`prompt_tokens` — Prompt token 数<br>`completion_tokens` — Completion token 数<br>`by_model` — 按模型分组的数据（数组，用于饼图）：<br> └ `model_name` — 模型名<br> └ `tokens` — 该模型消耗数<br>`by_time` — 按时间分片的数据（数组，用于柱状图/折线图）：<br> └ `time_bucket` — 时间片（日/周/月）<br> └ `tokens` — 该时间片消耗数<br>`cost` — 费用金额（可选，看 LiteLLM 是否提供） |
| **前端时间筛选按钮** | 「今天」— start_time=今日00:00, end_time=当前时间<br>「本周」— start_time=本周一00:00, end_time=当前时间<br>「时间段」— 用户自定义起止时间 |
| **备注** | 数据聚合在后端完成，前端直接拿渲染图表的数据格式 |

#### 接口 2.2 — Model 列表查询

| 项目 | 说明 |
|------|------|
| **用途** | 获取所有有 Token 消耗记录的 model 列表，用于筛选下拉框 |
| **请求字段** | 无 |
| **返回字段** | `models` — 模型名列表（数组）<br>例：`["gpt-4", "gpt-3.5-turbo", "claude-3-opus"]` |
| **备注** | 可选接口，也可以从 2.1 的 by_model 中动态提取 |

### 🎯 模块三：任务看板

> 数据源为 Hermes 看板 SQLite 数据库。目前只做展示，后续拖拽排序功能前端预留但不需要预留接口。

#### 接口 3.1 — 任务列表查询

| 项目 | 说明 |
|------|------|
| **用途** | 获取 Hermes 看板所有任务，展示在看板界面上 |
| **请求字段** | `status` — 按状态筛选（可选，如 `todo/backlog/done/blocked`）<br>`assignee` — 按负责人筛选（可选）<br>`priority` — 按优先级筛选（可选）<br>`project` — 按项目名筛选（可选） |
| **返回字段** | `tasks` — 任务数组：<br> └ `id` — 任务 ID<br> └ `title` — 任务标题<br> └ `status` — 状态（backlog/todo/in_progress/done/blocked）<br> └ `priority` — 优先级（P0/P1/P2）<br> └ `assignee` — 负责人<br> └ `project_name` — 所属项目<br> └ `updated_at` — 最后更新时间<br> └ `created_at` — 创建时间 |
| **备注** | 目前只做展示，后续拖拽排序功能在前端预留，接口后续再做 |

---

### 🤖 模块四：Agent 运行情况

> 卡片形式展示每个 agent 的运行状态和当前模型。页面加载时自动刷新，页面上保留手动刷新按钮。

#### 接口 4.1 — Agent 列表查询

| 项目 | 说明 |
|------|------|
| **用途** | 获取所有 Agent 的运行状态信息，以卡片形式展示 |
| **请求字段** | 无 |
| **返回字段** | `agents` — Agent 信息数组：<br> └ `name` — Agent 名称<br> └ `status` — 运行状态（online / offline / error）<br> └ `current_model` — 当前使用的模型（从 LiteLLM 获取）<br> └ `last_active_at` — 最后活跃时间<br> └ `total_tasks` — 总处理任务数（可选）<br> └ `last_error` — 最近一次错误信息（可选，status=error 时有用） |
| **备注** | 页面 load 时调用一次，手动刷新按钮再调用一次。不需要自动轮询 |
